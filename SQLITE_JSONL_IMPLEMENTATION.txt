实际改动

1. Teams 业务库
   schema 10 -> 11，通过现有事务 migration 增加部分索引：
   CREATE INDEX outbox_token ON outbox(conv_id,attempt_token,seq)
   WHERE attempt_token IS NOT NULL;
   查询、排序及发送状态语义保持原样。没有引入内存索引或另一套迁移框架。
   旧 JSON/blob 业务格式沿用已有 conversion 模块；本次未另写平行转换器。
   core/migrate 整包测试覆盖现有旧数据转换、所有权丢失、发布失败及重试。

2. history
   先读取来源 header，再复用不可变索引；完全未变时不再重载 history_session 全表。
   本进程成功写入后发布当前索引；发现其他连接改变 generation/offset 时重新加载。
   追加解析只读新增窗口；截断或替换重建。无有效新记录的半条尾行不复制完整 map。
   有效但无换行的尾记录临时展示，持久游标保留在尾记录起点。
   写入前检查哈希读取成功及来源身份没有变化，不发布无法确认的进度。

3. preview
   每个活动文件只有一份解析状态，保存解析位置、已提交位置、唯一去重状态和待提交增量。
   删除运行代码中的完整 seen 集合克隆/遍历差量，以及独立 dirty-path 注册表。
   旧克隆/比较实现只保留在测试中，供独立两连接测试作为参考。
   同一文件读取串行；固定 64 个锁，避免另造无限增长的锁表。
   全局内存条目锁不包含文件读取、数据库打开或关闭。
   保留 64 KiB/30 秒批量提交条件；没有新增后台 worker，也不是定时刷盘承诺。
   header 有效后才读取消息；文本读取不加载 seen，首次追加时才加载。
   解析、行边界检查及哈希尽量复用一个已打开的源文件描述符。
   解析/提交失败丢弃内存所有权，下一次从已提交位置恢复；不做逐项回滚。
   通过 generation/offset/ordinal CAS 防止两个连接重复追加；payload 读取后复核 header，
   避免另一连接淘汰或重建数据时发布混合快照。
   半条尾行使用临时去重 overlay，不污染完整前缀状态。保留末条完整 JSON 无换行的展示。
   预览窗口改为流式逐行读取；不再为整个窗口分配大 buffer。

4. catalog、名称与目录摘要
   缓存版本 3 -> 4，派生缓存按现有机制失效重建，运行路径只访问当前格式。
   index_source 复用来源进度语义，增加 thread_name 字段表，名称追加只解析新窗口。
   保留“最后一条有效非空名称生效”。名称尾记录无换行时也不会在重开后重复写库。
   summary 复用 session_meta 表，以负游标表示不可用于完整解析续读的摘要。
   消息数未知仍为 -1；摘要不能降级同一来源的完整元数据。
   每次发现过程按 256 个文件一批读取当前所需元数据；不加载已删除文件的旧缓存行。
   此批量快照随 loader context 释放；原有进程内元数据加速表限制为 4096 项。
   CloseCaches 同时释放数据库和进程内名称/元数据缓存。

5. 容量
   预览内存保留 64 项/估算 16 MiB，计入消息、seen 和未提交增量的主要容器开销。
   名称内存限制为 16 个来源 root；history 保留当前 store 所属的一份快照。
   preview SQLite 增加估算 128 MiB 的逻辑预算，仍保留 1024 个 session 上限。
   清理发生在写事务中；未变读取不触发清理或写入。超大项先淘汰，避免挤走全部小项。
   超大预览不额外保留内存副本；数据库文本按行读取，完整字符串仍需分配。
   预算是估算值，不是 Go 进程堆、SQLite 文件、WAL/journal 或整个 catalog 的硬上限。

刻意保留的边界

outbox.body 的网络 JSON、低频子集合事务重写、快照发布与 rename、正常 SQLite 页和索引写入、
Teams 历史保留策略、目录 WalkDir、完整文本接口均未重写。
没有新增 watcher、变更日志、分页协议、后台索引服务或通用缓存框架。
完整文本追加仍复制旧文本；流式 JSONL 的临时内存受最大单条记录影响，不是固定 64 KiB。
其他进程改变缓存后允许重载完整索引；正常追加仍有有界前缀校验读取。
业务升级没有反向 conversion；旧备份不能作为接收新消息后的无损降级方式。

安全与兼容性回归

新增 17 项 history/preview/catalog 回归，另有索引查询计划和业务库转换回归：
- 连续 20 次小追加分别从已解析位置续读，达到条件后只提交完整待写批次。
- 不完整尾行、完整但无换行尾记录及后续补换行，不重读旧前缀、不重复消息。
- 16 个并发读取者在同一路径上得到一致结果。
- 内存条目超预算淘汰后不遗留已修改的去重集合。
- SQLite 触发器注入提交失败：源文件回退、后续恢复及重开均保持消息完整。
- 解析期间替换源文件，不推进错误 checkpoint。
- 消息列表追加后再读文本，旧文本不丢失；调用者修改返回切片不污染缓存。
- header 读取后另一连接删除 session，不把空消息或空 seen 当有效缓存。
- quota 淘汰级联删除派生消息，源文件保持可恢复；临时尾记录继续展示。
- summary、名称在 CloseCaches 后复用持久缓存，名称追加保留最新有效非空值。
- 未变化但带半条尾记录的名称/history 重开不写库。
- summary 不覆盖同一来源的完整元数据；history 检出另一连接重建 generation。
- 600 文件的元数据跨批次读取完整，排除不在本次目录中的旧记录。
- schema 10 转换注入索引名称冲突：失败后版本仍为 10，原始载荷/token 和五种发送状态保留；
  排除冲突后重试至 11；未来 schema 明确拒绝。
- EXPLAIN QUERY PLAN 确认 token 查询使用 outbox_token。
