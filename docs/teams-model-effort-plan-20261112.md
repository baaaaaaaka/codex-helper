# Teams model/effort 切换：完整实施与测试计划

日期：2026-11-12。状态：已在隔离 worktree 实施，验证结果见 [实施验证记录](teams-model-switch-validation-20261112.md)。未提交、发布或部署，未重启宿主 Teams helper。

本版按用户最新要求简化，替代此前以多阶段恢复流程为中心的计划。此前时序风险清单中的必要约束已纳入本文；风险清单保留为测试输入，不将其中每个场景实现成独立状态分支。

## 1. 产品规则

一句话：切换期间暂存后续普通输入；旧执行停稳后，用最新有效设置继续同一任务。

- 支持 `model use <model> [effort]`，例如 `model use gpt-6.1-sol high`。旧别名保留；仅改变 effort 也进入相同流程。
- 给现有调度器增加一个“切换中”标记；平时行为保持原样。失败或结果不明沿用现有暂停机制，不新建自动故障恢复框架。
- 已识别的设置命令先阻止后续普通输入越过它；校验通过才中断旧执行。校验失败则报错、解除属于该请求的屏障，原任务继续。若另有有效切换或更早的未完成设置命令，不能错误清除其屏障。
- 同一次切换对同一个旧 attempt 只发起一次逻辑中断，期间连续设置只更新最新有效目标。原生队列删除与派发的竞态由已有 agent 适配层处理，不在 engine 中展开工具状态分支。
- 旧执行终态和 runner 收尾确认后，才允许下一次执行。RPC 返回成功本身不等于停止。
- 原请求尚未提交时，用新设置正常提交原请求；任务已经自然完成或明确取消时，不发“继续”。空闲换设置不唤醒历史任务。
- 已接收但未交付的当前任务普通消息，按顺序作为新执行的输入；没有这种新消息时才使用固定续接 prompt。已收到但附件/ASR 未就绪不等于没有新消息，按现有流程等待或明确失败。
- 明确排队的新任务、审批回复和问题答案保留原有语义，不做自然语言意图分类，也不把所有消息强行拼成当前任务的补充。
- 用户取消命中的任务不自动复活；只取消排队消息时，不误取消当前任务的续接。
- CXP 完成接收与处理后才能保证上述顺序。不能承诺用户在 Teams 点击发送时，后端尚未收到的信息就已经生效。

第一版仅覆盖 CXP 自己管理的普通任务。外部 TUI 的独立执行、原生 goal 自续接、已有子代理和跨机器任务不承诺一起切换。检测到不能协调的执行来源时，在中断前说明限制，不静默退化并宣称当前模型已切换。

不使用 `turn/settings/update` 的 model/effort 更新，不启用 `step_model_switching`，不因切换终止 helper 或强杀 Codex app-server。

## 2. model/effort 的统一规则

1. 将 model/effort 作为完整目标一起校验，通过同一个应用入口保存；不为两个字符串再建立配置框架。组合命令使用纯解析函数，effort-only 和 reset 复用既有默认解析规则。
2. model 与 effort 一次校验、成对保存。明确指定的任一项无效，均不部分应用。
3. 仅换模型时：保留目标模型支持的显式 effort；不支持则使用目标模型默认值并说明。目录以 Codex 返回为准，不维护新的模型白名单。
4. 连续 patch 基于最新有效目标解析：切到 B 后再设 high，修改的是 B 的 effort，而不是仍在运行的 A。
5. 先匹配完整模型 ID/显示名，再识别可选 effort，保留显示名和旧别名兼容。同模型换 effort 也是有效变更。
6. 全局默认继续使用新聊天创建时的快照语义；reset 重新解析默认值。不广播改写已有聊天。
7. Control/Work 共用更新入口，但本任务不顺带改变 Control 的既有默认策略。历史 pending 字段和旧 source 值只做必要兼容读取，避免同时大规模重写配置与数据。
8. 不重复保存目标与 pending 两套设置。当前执行保存自己的 model/effort 快照，状态展示明确区分目标与当前执行。

## 3. 续接输入

固定短英文 prompt，模型切换与自动失败重试共用：

> Continue the active unfinished task from its current state. Keep the previous response language unless the user requests otherwise. Verify interrupted actions before retrying; do not repeat completed work.

- 有当前任务的新普通输入：使用这些输入继续任务，不额外再启动一个只包含“继续”的 turn。所有已就绪的连续补充按原顺序在首次采样前提供，保留消息边界和来源；明确排队的新任务不混入。
- 没有新普通输入：仅发送上面的内部指令，不重放原始请求或图片。
- 原请求确认从未进入对话：走原请求的正常提交路径，不发送空泛续接。
- 自然完成后仍有新消息：按现有普通输入规则处理，不人为附加“继续已完成任务”。
- 内部输入不镜像成用户亲自发送的 Teams 消息，不改变用户明确的停止、任务替换或语言指令。
- 同一任务继续使用原来的工作目录、权限、文件状态、artifact 输出目录和 manifest 契约。新的 Codex turn ID 不自动定义新的用户任务或输出目录。
- 续接使用同一活动任务的 envelope 语义，不沿用普通新请求 envelope 对历史任务已完成的假设。

不在 prompt 中写模型名、切换原因、预算或调度过程；这些事实由 CXP 记录。工具副作用不会回滚，后台任务也可能继续存在，不能用 prompt 代替执行状态核对。

## 4. 最小内部设计

继续使用当前命令队列、runner、steer、turn/inbound 记录和暂停恢复机制，不建立第二套队列或通用工作流引擎。

### 4.1 数据只记录必要事实

- 聊天目标 model/effort 及递增的设置版本。
- 每个会话最多一条未完成切换记录：绑定原 thread、原逻辑任务、原 attempt，并关联已准备的续接执行 ID。目标设置仍以聊天记录为准，不重复存一份。
- 内部续接复用已有 turn 状态，增加明确的续接来源/原任务关联；输入沿用已有 inbound/turn 标识，记录这次执行领取的输入集合。若现有关联不足，只补必要的关系字段，不新增一份消息历史。
- 切换记录存在表示切换尚未收尾；新执行 queued/starting/running 仍用原有 turn 状态，不再平行维护一套阶段枚举。
- 校验期间的投递屏障由已有待处理设置命令和会话标记表达；启动恢复必须先恢复这些屏障，再允许 runner 工作。不能只持有进程内布尔值，导致崩溃后跳过尚未完成的切换。

Schema 按实施时上游版本增加一次必要迁移，不预设固定版本号。新增字段应采用兼容默认值，不扫描重写全部历史；终态记录沿用现有保留策略，未完成切换记录每会话至多一条。

### 4.2 顺序与并发边界

1. 设置命令处理只负责校验、保存目标和唤醒调度器，不占命令 worker 等待整次中断完成。
2. 切换标记同时约束 `tryStart` 和 `trySteer`；收到切换前已经在途的 steer 要先核对，不能假设 RPC 成功就已持久化。
3. 中断只针对记录绑定的旧 attempt，不能用“这个聊天当前是谁”重新寻找目标。
4. 旧执行结束后，由现有 runner 在一次准入事务中读取最新设置版本，领取准确的输入集合，创建或领取唯一的续接执行。
5. 该准入事务是本次执行设置和输入的截止点。之后收到的设置是下一次切换；之后收到的普通消息继续待投递，按已有规则进入新 turn。
6. 迟到回调只有仍匹配 thread、原 attempt 和关联续接身份时才能清理记录，不能清掉较新的切换。等待网络或工具时不占全局锁。

### 4.3 结果不明时的简单规则

确认已进入原 thread 历史的输入不重发；明确拒绝或确认未提交的输入仍待交付。无法确认中断结果、输入保留或新 turn 是否接受时，暂停并报告，不自动猜测重发。

不要求新增一个无限恢复系统，也不承诺外部操作恰好执行一次。既有恢复查询能证明结果时使用它；证明不了就停在现有人工处理边界。通知失败不得导致执行重试。

## 5. 实施步骤与代码范围

### P0：先验证接口边界

在隔离环境中，用真实 Codex CLI 加模拟 Responses 服务验证：正常 start 的接受/记录边界、steer 接受但尚未采样时中断的历史保留、原生队列删除/派发竞态，以及终态与历史可读顺序。

依据当前真实行为确定可用的交付证据。尤其不能因为存在 `clientUserMessageId` 就假定服务端提供幂等去重。不能可靠确认的组合明确进入暂停路径，不先堆叠自动重试补偿。

完成标准：协议级测试能够稳定控制并复现这些边界，记录支持版本与未确认行为，再实现自动续接。

### P1：统一解析与提示词

- `internal/core/engine/modelcmds.go`：支持组合语法，统一 model/effort/reset 的目标解析与成对保存；修改“当前执行保持旧模型”的状态文案。
- 抽取小的纯解析函数，供创建聊天与设置命令复用；不新建模型配置框架。
- `internal/core/engine/runner.go` 的自动重试，以及 `internal/codexrunner/capacity_retry.go` 的恢复指令，使用同一段短英文文本；共用一个无依赖的小常量来源，不改变失败重试触发条件和预算。
- 更新对应单元/E2E 中锁定字面量 `continue` 的断言，转而验证恢复语义、语言条款、同 thread、原请求不重发和内部输入不镜像。

完成标准：参数错误不产生部分写入，重复同一目标不重复操作，已有默认与别名兼容通过。

### P2：加入最小切换协调

- `internal/core/engine/receive.go`、`commands.go`：设置命令的顺序屏障和快速提交；保持取消、状态查询、问题回复的独立通道。
- `state.go`、`runner.go`、`steer.go`：一个切换标记约束启动与输入投递；仅增加设置切换的停止原因，禁止沿用会强杀后端的用户取消路径。
- `internal/core/codexagent/agent.go`、`internal/core/codex/turn.go`：复用定向中断、启动前停止和原生队列处理；等待旧执行终态，不新增模型实验 RPC。
- `internal/core/store`：成对目标、设置版本、有界切换记录、内部续接关联及一次领取输入的事务操作。

完成标准：无重叠执行；连续变更使用最新有效目标；B 已准入后收到 C 就按第二次切换处理，不尝试追溯撤回已发出的请求。

### P3：衔接输入、取消、收尾与恢复

- 复用现有输入记录，为当前任务准备有限的有序输入快照；等待已收到但附件未就绪的普通输入，不将它误判成没有输入。
- `envelope.go`：续接与新增普通输入保持活动任务语义；保留输出目录、图片与引用关联，不重放已确认历史。
- `turncmds.go`：取消当前任务时也能取消“等待续接”，即使两次原生执行之间暂时没有 running 指针；裸 cancel、cancel queued 与 cancel all 保持现有目标规则。
- `runner.go` 的 finish/clearRun/retry/reconcile：旧终态先处理，再决定唯一续接；自然完成不重启，旧重试计时器不与续接竞争，结果不明沿用暂停。
- 处理同步问题/审批失效，保留仍有效异步问题；不把旧卡片答案投到不相关的新请求。
- 恢复时先核对已有续接是否接受或结束；不得因 helper 重启、通知未发送或旧回调迟到再次提交。

完成标准：各处崩溃后能证明安全恢复或明确暂停；不存在已取消任务复活、消息丢失、盲目重发和输出归属漂移。

### P4：行为契约、文档与 CI

- 更新命令帮助、状态展示及现有“运行 turn 不变，下一轮生效”的行为说明，明确同一用户任务中断后自动续接。
- 更新 `internal/e2e/scenarios/commands/model_switch_busy_test.go`：该场景当前锁定旧语义，必须重写为中断、同 thread、新设置自动续接及取消边界，不能只更换提示字符串。
- 新建核心场景并保留普通输入、队列、问题、失败重试和重启场景的回归约束。
- 核对 CI 的 package 分片及 `-run` 过滤，保证新测试被执行，而非只编译、skip 或匹配零测试。

本任务止于代码、文档和测试完成。提交、PR 或发布按用户后续要求处理，不部署或重启安装中的 Teams helper。

## 6. 测试计划

所有异步测试使用 channel/latch 或协议事件控制交错，不靠 sleep 猜测边界，也不把多次重复运行当作顺序正确的证明。

| 层次 | 必测内容 | 核心断言 |
| --- | --- | --- |
| 解析单元测试 | 组合语法、旧别名、显示名、effort-only、reset、无效输入、同目标、A→B 后 effort patch | 完整目标对正确；失败无部分保存；默认策略不漂移 |
| Store 单元测试 | 设置/切换原子提交、并发版本、输入领取、唯一续接、迁移、事务失败、旧字段读取 | 失败不留下半个切换；输入关联可核对；每会话一条未完成记录 |
| Engine 确定性交错测试 | 命令校验屏障、同目标、A→B→C、A→B→A、有效后接无效、终态前后新消息 | 无旧模型抢收后续输入；中断不膨胀；最新有效设置在准入时生效 |
| 生命周期与取消 | 空闲、未提交、启动中、等待续接、自然完成、取消当前/queued/all、暂停/关闭 | 原请求只在需要时提交；已完成/取消任务不复活；排队取消语义不变 |
| 输入与 envelope | X/切换/Y/Z、快照后新消息、未就绪附件、ASR 失败、引用和图片、问题答案、活动任务提示、输出目录 | 新输入顺序与边界正确，旧输入不重放，补充不会被包装成旧任务已完成 |
| 协议/agent 测试 | 中断响应早于终态、定向 turn、原生队列删除/派发、steer 迟到、接受但未记录、RPC 未知结果 | 只操作绑定 attempt；旧执行未停不准入新执行；不确定时暂停 |
| 重试与故障恢复 | 容量退避同时换模型、旧计时器、用户 retry、提交附近崩溃、接收后落盘失败、重复事件和通知失败 | 一次执行准入；不重复任务；通知失败不触发执行；恢复无可证明结果就暂停 |
| 黑盒 E2E | Teams 连续消息、命令回复、切换中取消、繁忙换模型自动续接、问题回复、重启恢复 | 无用户追加“继续”；同 thread；新 model/effort；内部指令不镜像；状态反馈不谎报 |
| 原生 Codex 离线契约 | 真实 CLI + 模拟模型服务，覆盖压缩、工具、审批、输入保留和不同接受时机 | 实际请求顺序、model/effort、输入次数和 tool 结果可观测，不以 fake agent 代替协议验证 |
| 真实推理补充验收 | 中文任务、切换 effort、用户明确换语言、中断工具后核对已有结果 | 实际语言保持与继续工作可见；文本断言不冒充模型行为证明 |

### 6.1 关键交错用例

在下列同步点前后分别插入普通消息、第二次模型变更或明确取消：命令接收、校验完成、目标提交、steer 发送/响应、中断发送/响应、旧终态、runner 清理、续接输入快照、新 turn 发送/接受、成功通知。

至少包含：

- 切 B → X，B 尚在查目录；X 不得先进入 A。
- X → 切 B → Y → 切 C → Z；在首次续接准入前已有效的 C 生效，Y/Z 保持顺序，X 已记录则不重发。
- A→B→A，中断已经发出；恢复动作不因目标等于 A 而丢失。
- 同一目标重复请求，和新模型已准入后再切换；分别验证不重复操作和确实需要第二次切换。
- 原请求未接受、已接受但还未记入历史、已记录未采样、steer 在途、中断后历史可读，分别验证原请求/续接/暂停选择。
- 切换 → 新附件消息尚未就绪；不得抢先发内部“继续”；下载或 ASR 失败后按既有规则明确处理。
- 切换 → “改用测试环境”在快照前到达；第一次采样就收到修正。快照后到达则保持待投递，不错误标记交付。
- 取消当前任务后再改模型；不复活原任务。取消 queued 时则不误取消当前续接。
- 旧执行在 interrupt 附近自然完成；保留答案，不启动空续接；新消息仍正常处理。
- 切换与自动失败重试、手动 retry 同时发生；只允许一个后续执行。
- 待审批/同步问题中断，旧答案迟到；不授权或回答新请求。异步问题仍有效时保留其有效性。
- 提交前、提交后但本地未确认、执行完成但通知未发、旧 thread 被替换等故障点；安全核对或暂停，无盲目重发。
