# Fix forked Teams conversations retaining a Codex writer

## Why

A newly forked Teams conversation could reject its first request with an active
writer error. The helper created the child in the parent's warm app-server,
which retained the child's writer ownership while another server tried to run it.

## What changed

- Create each fork in a separate temporary app-server managed by the existing
  process pool. Confirm its exit before returning the child to the Teams flow.
- Keep the parent running. Run cleanup after success, RPC failure, cancellation,
  or panic. Retain process ownership records when exit cannot be confirmed.
- Persist the native child, omit the response's inherited turns, and defer goal
  continuation until the owning conversation can load it. Reject an empty ID.
- Report an uncertain fork result without claiming that nothing changed or
  retrying the request automatically.
- Keep the existing gated model-switch ordering test independent of the
  short fixture interrupt deadline under the full race sweep. Production
  timeouts and the dedicated unconfirmed-stop timeout test remain unchanged.
- Add focused lifecycle tests and native fork contracts to the existing Linux,
  macOS, and Windows CI matrix, including older-version stdio coverage.

## Validation

The fork implementation was based on upstream
`91542ffed726ce7ef8440b4ce47a734c9b34305a` and committed as `db2dd464`.
Its main CI passed all 22 jobs. RC.40 was blocked before packaging by an
existing gated model-switch test that exhausted its fixture interrupt deadline
under the full race sweep. This candidate includes the focused test correction
and uses a new tag; RC.40 is retained. Before the follow-up commit, upstream
main at `db2dd464` was fetched and confirmed included by a fast-forward merge
check.

- The production-path regression reproduces the active writer failure with the
  upstream implementation and passes with this fix.
- Native Codex 0.167.1 passes stdio and shared-connection tests. Codex 0.131.0
  passes the production-path stdio test. Tests hold the parent turn open while
  the child runs in another process, using a local synthetic Responses server.
- The focused model-switch race tests pass 10 iterations with `-parallel=16`,
  including both 100 ms unconfirmed-stop cases (127.694 s). Only the gated
  ordering test fixture changes; its assertions and production timeouts do not.
- Core and channel package tests pass in the isolated Docker harness. Relevant
  Linux race tests pass; one host proxy-environment assertion was excluded from
  that race command and passed separately in the clean container's full run.
- All three E2E shards pass: 185 scenarios and 1,567 checks across 15 packages.
- Go vet, actionlint, formatting, whitespace checks, and Windows amd64/macOS
  arm64 test cross-compilation pass. Native platform and packaged-release gates
  execute in the main CI and full Release workflow before publication completes.
- The path runs only on an explicit fork: one cold server start and bounded
  shutdown, with one process-record insert and removal. It adds no idle work,
  full-history scan, full-state rewrite, or growing persistent format.

Detailed local evidence and environment limits are in
[`docs/teams-fork-validation-20261116.md`](../teams-fork-validation-20261116.md).

## Compatibility

The base helper version remains `v0.1.23`. The race follow-up changes test
configuration only and preserves the model-switch assertions. There is no database or configuration
migration, new polling loop, or automatic fork retry. Existing history cutoff,
Teams history import, child binding, and link publication ordering are preserved.
Each explicit fork pays for one extra app-server startup. Local native tests use
synthetic model responses; real Microsoft Graph delivery was not tested locally.
The running development-host helper is not updated or restarted by this release.
