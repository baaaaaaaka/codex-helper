# Teams links, discussion reads, search, and attachment downloads

## Why

Teams HTML conversion kept link labels but removed their destinations. Agents
could see “task description” without the URL. They also needed a direct way to
read a shared discussion or selected attachment without starting a helper or
scanning all chat history.

## What changed

- Preserve named link destinations in Codex input, including normal and queued
  prompts, control questions, and quoted messages. Command parsing and existing
  visible-text hashes keep their behavior.
- Add `cxp teams read` for linked messages and chat/channel resources, explicit
  chat `--before` and `--latest` windows, channel `--replies`, and batch reads of
  known message refs. Overlapping windows share one message table.
- Add `cxp teams search` for indexed candidates and summaries. Read selected refs
  to obtain original messages. Channel hits without a reliable reply parent
  remain unresolved.
- Add `cxp teams fetch` for selected SharePoint/OneDrive reference files and
  hosted images on chat or channel messages. Validate source, version, size,
  redirects and resume offsets; keep Graph credentials off download hosts and
  refuse existing final outputs.
- Bound requests, response bytes, text, messages and time. Versioned JSON and
  text output include range states and continuation cursors. Keep the original
  page query during mid-page continuation and reject edited body continuations.
- Document these capabilities, their costs and their limits in the bundled cxp
  skill. The interfaces do not select a default task or handoff workflow.

## Validation

The first candidate was blocked by the repository black-box boundary check:
its new E2E scenario imported product response types. This candidate uses
independent CLI JSON response views instead, keeps every behavioral assertion,
and adds explicit output-version checks. The boundary rule is unchanged. Version-bearing E2E snapshots now expect the
new base version v0.1.23; their other content and functional checks are unchanged.

Local validation passed the complete CLI package, core/channel CI race groups,
final Teams and fake Graph race tests, skill tests, vet, formatting and whitespace
checks. Ephemeral Docker tests exercised the production CLI read/search/fetch
flow without a running helper, and the Graph-to-Codex named-link input path.
Native Windows tests exercised the new commands, downloads and resume behavior.

Tests cover sparse and empty pages, foreign or changed pagination, ignored
filters, Unicode/body continuations, channel reply pages, controlled concurrent
windows, mixed batch errors, request/byte/time budgets, interrupted or expired
file downloads, ignored or invalid ranges, changed sources, and output safety.
A 50-message regression returns 45 messages then the remaining 5 without repeats.
The fixed subcommand-list test now includes only the three new command names.

Read-only real Graph samples passed direct and combined reads, search followed
by batch reads, an eight-message channel thread, a complete 17991-byte reference
file, a complete 116230-byte hosted JPEG, and 45+5-message cursor continuation.
No message text, IDs, credentials or temporary download URLs appear in these notes.

A 100-message local fixture uses three logical requests, about 119KB of response
data and 90KB of output, at about 4.9ms and 3.75MB allocated per operation on the
test host. Ordinary inbound conversion showed no material change. Preserving
1000 rich-text links adds parsing work: about 3.51ms to 5.31ms for an 85KB body.
Read/search add no persistent message cache or background scanner. Fetch writes
only the selected output and its bounded resume state. These measurements are
workload observations, not latency guarantees.

## Compatibility

This is an additive CLI release with no new business-state schema. Existing
bindings, receive cursors, echo hashes, old file refs and helper lifecycle keep
their behavior. Read commands use the configured read identity and an existing
proxy when configured; they do not widen scopes, switch identity on denial, or
start/retire a proxy daemon. Normal authentication cache refresh can still occur.

Bare read selects only its target. History, replies and downloads require an
explicit choice. Search is an index view, not proof that a chat has no other
messages. Graph calls are not a transaction snapshot. Minimum scopes, guests,
cross-tenant/shared-channel access, other users' files, very large downloads and
unusual filesystems remain unverified. File access has separate permissions from
message access. This release does not install or restart a running helper.
