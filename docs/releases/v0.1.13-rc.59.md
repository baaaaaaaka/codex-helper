# Safe ChatGPT desktop entry migration with legacy Codex compatibility

This prerelease updates `codex-proxy app` for OpenAI's desktop entry migration.
Current macOS distributions expose Codex through `ChatGPT.app` and the
`ChatGPT` executable, while older installations still use `Codex.app` and the
`Codex` executable. Windows retains the `OpenAI.Codex` Store package identity
but package manifests can expose either `ChatGPT.exe` or the legacy
`Codex.exe`.

The helper now follows the current entry without dropping support for already
installed or older desktop packages.

## Root cause

The launcher assumed the legacy bundle and executable names in several places:

- macOS discovery, DMG extraction, installation, and launch required
  `Codex.app/Contents/MacOS/Codex`;
- Windows direct launch assumed `app\\Codex.exe`, and AppX fallback selected the
  first manifest application instead of the Codex-capable entry;
- live and network-install tests only looked for a `Codex` process.

Changing only those strings would not be safe. A classic ChatGPT installation
can also occupy `ChatGPT.app` and is signed by OpenAI, so a Team-ID-only check
could mistake it for Codex or overwrite it. Windows manifests can also contain
multiple applications or move the executable away from a fixed `app` path.

## What changed

- macOS discovery prefers the current `ChatGPT.app` entry, then falls back to
  `Codex.app`. Both bundles accept their expected executable first and the
  alternate executable second, preserving transitional package layouts.
- Installed and downloaded macOS bundles must have the exact bundle identifier
  `com.openai.codex` and OpenAI Team ID `2DC432GLL2`, in addition to the existing
  strict code-signature and Gatekeeper checks.
- A separately installed classic `ChatGPT.app` is never replaced. If the
  current name is occupied by a non-Codex app, the unified Codex bundle is
  installed safely as `Codex.app`; if both supported names conflict, the
  operation fails closed.
- Windows reads executable locations from the AppX manifest and prefers
  `ChatGPT.exe`, then `Codex.exe`, while retaining fixed legacy paths as a
  compatibility fallback.
- AppX activation uses the manifest entry associated with `ChatGPT.exe` or
  `Codex.exe`. A single unknown entry remains supported for forward and legacy
  compatibility, but multiple unknown entries are rejected rather than
  launching an unrelated application.
- Existing Store product ID `9PLM9XGG6VKS` and package identity `OpenAI.Codex`
  are unchanged, so installation and update continuity are preserved.

## Compatibility and safety

- New and old desktop entries can coexist; the current Codex-capable entry wins
  deterministically.
- A broken or non-Codex current entry does not hide a valid legacy Codex app.
- Explicit unpackaged `--app-path` behavior remains available on both platforms.
- Windows proxy mode still refuses AppX fallback when doing so would lose the
  required Chromium proxy arguments.
- Linux outside WSL remains unsupported, and WSL continues to launch the
  Windows Store package.

## Validation added

- Unit tests cover current-only, legacy-only, mixed executable names,
  coexistence, current-entry preference, broken-current fallback, exact signing
  identity parsing, classic ChatGPT rejection, safe name-collision installation,
  and ambiguous collision refusal.
- Windows PowerShell integration tests execute the generated selection logic for
  current-first, legacy-only, single-unknown, and ambiguous multi-entry
  manifests, plus nonstandard manifest executable paths.
- Live GUI tests and process detection accept both `ChatGPT` and `Codex` names.
- macOS network-install CI downloads the current official DMG, requires the
  ChatGPT entry, verifies the exact bundle identifier and Team ID, and observes
  the launched process.
- Windows network-install CI installs the real Store package, validates its
  manifest and executable path, and observes either supported process name.
- The complete Go suite, focused desktop regressions, Windows amd64
  cross-compilation, host Windows PowerShell integration tests, Shell and
  PowerShell parsing, pinned Actionlint, formatting, and diff checks pass before
  the release tag is created.
