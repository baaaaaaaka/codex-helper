## Why

An interrupted first conversion could leave a lease file without a completed database. The next start treated the lease as proof of conversion and opened an empty store, so the original Teams conversations stopped receiving replies. A long-running watchdog could also stay on the previous runtime after an update.

The rc.73 Windows CI caught an additional failure: a sharing violation while replacing the runtime pointer could end the watchdog loop. That candidate was stopped before publication. This candidate keeps the watchdog alive and retries safely. The rc.74 release recheck then caught the other side of the Windows conflict: ordinary read handles omitted delete sharing and could block atomic activation. Those failed candidate tags are preserved; neither was published. The rc.75 release-only Windows script gate also caught a POSIX assumption in the new test fixture before packaging; that tag is preserved without a published release. The rc.76 repeat gate then exposed a shutdown publication race and mutable queue responses in the fake Codex backend; packaging was stopped and its tag is retained. The rc.77 repeat gate additionally found an admission window between steering and starting a new execution; its tag is also retained without publication. Two other rc.77 checks were blocked by HTTP 504 responses while downloading GitHub release assets, independently of source assertions.

## What changed

- Recheck native-turn routing while claiming an ordinary message in the start transaction. Input admitted after the preceding steer check remains queued for the next steering pass, so an uncertain delivery still pauses without replay. Explicit queued requests and idle execution retain their existing paths. The check uses the existing in-memory native-turn cache; it adds no file I/O, history scan or polling.
- Publish local shutdown intent and reply protection before creating the shared stop file. A heartbeat no longer exits this process before its shutdown reply; if recording the stop fails, restore normal admission and wake queued work.
- Keep fake Codex queue response maps immutable during dispatch and snapshot list slices before releasing their lock. Add deterministic regressions and a dedicated CI race check for the fixture.
- Select the store anchor first, then prepare the database after acquiring its lease. Resume unfinished conversion, and open the database before publishing the lease.
- Refuse to replace a missing published database with an empty store. Reuse completed conversions even if startup stopped before writing the marker or activating the lease.
- Carry cancellation and ownership into the converter. Check ownership between stages and immediately before publishing the completed database. Cancel startup retries as soon as another owner takes over.
- Make the watchdog follow runtime activation and rollback through the stable launcher before checking helper health. Compare against the binary build version so older launchers without a pinned version marker work too.
- Open Windows runtime pointers with read/write/delete sharing and replace them through Go’s rooted rename, which uses Windows POSIX replacement semantics. This permits atomic activation and rollback while readers remain open. Keep Unix reads unchanged and preserve long-path support. Hold old readers through replacement in regression tests and require both old-reader and fresh-reader contents to remain correct.
- Use one loop error policy for runtime refresh and health checks. Log refresh errors, skip health collection in that iteration, and retry after the normal interval. Failed restarts also retry without allowing the old runtime to judge health.
- Add unit, real-process and black-box E2E coverage. Require the startup gate on Linux, Windows and macOS, repeat the seven critical Linux E2E cases three times, and include CLI race checks. The release workflow reuses the same CI gate.
- Make the startup-gate script fixture use native Git Bash and the current Python interpreter on Windows, with paths containing spaces. Keep the same missing-test and failure-propagation assertions on every platform.
- Update the restart queue scenario to request explicit independent tasks for both queued prompts. Ordinary shared-Codex messages may steer the active turn; the scenario continues to require exact-once execution, ordering and no replay after a second restart.

## Validation

- A deterministic admission-boundary test rejects the old implementation and covers active ordinary input, explicit queue input and idle input without sleeps. The deferred input reaches steering once, preserves its uncertainty notice and pauses without a new execution. The boundary regression passed 100 race rounds and the full uncertain-input scenario passed twenty race rounds. Full engine coverage and core/channel race suites passed; Windows amd64 and both macOS architecture engine suites cross-compile with CGO disabled.
- The shutdown publication test fails deterministically with the old order and passes with the corrected order; shutdown regressions passed twenty rounds. Complete engine coverage and race suites and the shutdown E2E scenarios protect the transition and failed-write rollback.
- The fake queue response test rejects the old shared-map mutation. Its corrected version passed 1,000 focused race rounds; full E2E and five repeated backlog-conversion scenarios validate the fixture.
- Native Windows PowerShell validation passed all nine startup-gate fixture tests and the complete 136-test script suite (48 existing platform skips).
- Baseline validation passed in the development skill's isolated Docker environment: the complete non-scenario Go suites, all E2E packages, relevant race checks, vet, and all script tests. The final admission guard also passed complete core/channel race checks and the affected shared-home, turn and restart E2E packages. A preliminary 100-round full-chat batch reached its five-minute total budget without a race or assertion failure; the replacement twenty-round batch completed successfully in 106 seconds.
- Four legacy fixture combinations cover v0.1.20 and rc.59 in JSON and SQLite-WAL forms. All 168 injected cancellation and ownership failures preserve the old data and recover the original chat and thread bindings.
- Pointer-read and restart-failure recovery tests fail against the rc.73 loop and pass after the error-policy refactor. Native Windows CI asserts a genuine external sharing violation before testing recovery in both launcher contexts. Deterministic replacement tests hold a pointer reader open while activation occurs; an overlay restoring the old Windows reader must fail those tests.
- All seven critical E2E cases passed three consecutive rounds. They cover interrupted retries, a crash during import, takeover while waiting or importing, a missing published database, and watchdog upgrade/rollback through both current and older launcher contexts.
- A deliberate mutation that disables conversion ownership checks makes the real-process E2E fail on unsafe database and marker publication. The protected version passes.
- Replacing the watchdog comparison with the old implementation makes both the legacy unit cases and the real release-binary E2E fail on the unchanged executable.
- Windows amd64 and macOS amd64 CLI/converter test binaries cross-compile with CGO disabled; the final CLI also compiles for macOS arm64. Native platform execution is required by CI for this release commit.
- Warm database-open checks remain about 64 ms with either a 1 KiB or 32 MiB old backup, with unchanged allocation volume. A 20,000-iteration Linux pointer-read benchmark (three rounds) improved from about 6.3 to 5.6 microseconds, with allocations reduced from eight to seven per read. These measurements exclude network and Codex startup; Windows performance was not measured.
- The full restart E2E package passed five rounds with explicit queue inputs; the shared Teams/TUI input scenario passed three rounds, covering ordinary steering and separate queued execution.
- Required main CI and release checks run against this exact commit; the release workflow blocks packaging and update-index publication on their required dependencies.

## Compatibility

- The CLI base version remains v0.1.22. This change adds no store schema or protocol version.
- Automatic legacy conversion still supports v0.1.20 and rc.59. Other old store versions retain their existing refusal behavior.
- This prevents new empty-store recovery errors. It does not merge or repair an empty database already published by an older defective version.
- A watchdog binary from before this fix must first be switched to the updated runtime through the managed update/restart flow. Existing old processes do not gain the new refresh logic by changing files alone.
- Real NFS outages, machine power loss, and live Teams delivery were not reproduced locally. The local E2E suites use private state and fake Graph/Codex services.
