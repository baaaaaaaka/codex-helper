# v0.1.22-rc.85

## Why

The release compatibility smoke found that candidate-owned updates rejected a
valid target version when the updater passed it without the `v` prefix. The
published runtime reports the same semantic version in normalized form, so the
candidate was installed but could not be confirmed.

## What changed

- Normalize the requested target before comparing it with the immutable
  runtime's reported version.
- Reject invalid target versions before probing the runtime.
- Exercise the full candidate apply path with the unprefixed target format used
  by the production updater.

## Validation

- `go test ./internal/candidateupdate ./internal/update` passes.
- `git diff --check` passes.
- Main CI and the release workflow validate the change, including split-entry
  upgrades from older helper releases and packaged TUI startup on supported
  platforms.

## Compatibility

Both prefixed and unprefixed semantic versions remain supported. This fix does
not change the update protocol, on-disk state, or runtime selection behavior.
