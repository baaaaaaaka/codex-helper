# v0.1.22-rc.50

## Why

Teams recovery could repeatedly revisit deferred control rows, authentication
failures, malformed recovery results, or source-rewrite checkpoints without a
durable row-local disposition.  At the same time, common SQLite outbox writes
could hydrate the cold history-watch JSON projection while holding the state
lock.  These paths made a provider outage or a large history corpus look like
a global synchronization stall.

## What changed

- classify Graph transport, response, authentication, and external-outcome
  failures at the request boundary;
- durably back off or hold deferred rows that cannot be safely replayed, while
  preserving the no-automatic-replay rule for unknown POST results;
- keep account/global read throttling separate from independent durable writes;
- harden source-proof and HistoryWatch recovery fences across JSON and SQLite;
- use the native Windows per-file USN revision when proving a source rewrite;
  if the volume has no usable USN journal, the automatic proof remains
  disabled rather than treating writable `LastWriteTime` or basic-info time as
  a durable source revision;
- keep ordinary SQLite outbox admission on a selected hot path instead of
  loading the full cold history-watch projection;
- keep the dedicated owner-liveness SQLite handle on a short busy bound, so a
  foreground writer cannot trap the heartbeat inside `BEGIN IMMEDIATE` and
  starve poll workers;
- add regression coverage for deferred recovery, auth failures, source-proof
  boundaries, SQLite hot-path behavior, and an isolated Docker acceptance
  scenario covering account/global 429, intermittent reads, unknown POST, and
  durable completion.

## Validation

- `go test ./internal/cli ./internal/teams/store ./internal/teams -count=1`
- `go test ./... -p=1 -count=1 -timeout=20m`
- `go vet ./...`
- bounded Docker acceptance with `--network=none`, no Teams token, fake Graph,
  account/global GET 429, intermittent recovery, and unknown POST
- focused normal and race regression coverage for owner heartbeat under a
  foreground SQLite writer, plus the previously failing slow-inbound listener
  scenario
- `git diff --check`

The live Teams helper and live SQLite scope were not restarted or mutated by
the release preparation.  Ambiguous existing outbox rows remain fail-closed
and require exact remote reconciliation.

## Compatibility

This is a prerelease.  Existing JSON state remains supported as a fallback;
SQLite projection trust and owner/lease/frontier CAS fences remain required.
The release does not automatically replay rows whose Graph POST result is
unknown, and it does not perform live database repair.
