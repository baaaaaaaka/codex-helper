# v0.1.22-rc.16

## Why

`v0.1.22-rc.15` restored the rc8 execution-anchor safety fixes to the
current `main` line. Its exact-SHA validation then exposed two CI workflow
mistakes carried by that merge: a duplicated runtime-safety invocation and an
unbalanced SQLite targeted-test regexp. This follow-up keeps the runtime
repair and makes the release validation reproducible.

## What changed

- Removed the duplicate runtime-safety test invocation now covered by the
  shared shard script.
- Corrected the SQLite store targeted-test regexp so all intended migration
  and compatibility tests execute on Linux, macOS, and Windows.
- Retained the durable unresolved-execution anchors, cancellation fences,
  source-proven transcript checkpoints, parent-fork fences, and continuation
  barriers restored in rc15.
- Kept the current durable Teams routing and queue-only fork behavior intact.

## Validation

- `python3 -m unittest discover -s scripts/tests -p 'test_*.py'` — 138 tests
  passed, with only the repository's expected skips.
- `go run github.com/rhysd/actionlint/cmd/actionlint@v1.7.11 -color`
- Corrected SQLite targeted tests passed on the local workspace and on all
  three CI operating systems.
- `env -u CXP_RUNTIME_DISABLE go test ./internal/helperruntime -count=1 -run '^TestLaunchKeepsExplicitSameBasePrereleaseActive$' -v`
- Exact-SHA main CI passed after one documented Windows full-suite timeout
  retry; native proxy validation also passed on macOS and Windows.
- Focused history, transcript, execution-anchor, SQLite/JSON compatibility,
  and bounded benchmark/disk-budget checks from rc15 remain unchanged.

## Compatibility

This is a CI-only follow-up to the `v0.1.22` prerelease line; runtime behavior
is unchanged from rc15. Durable JSON and SQLite fields remain backward
compatible, and no public Teams message protocol changes. This prerelease is
for validating the repaired release line and does not replace a stable
release.
