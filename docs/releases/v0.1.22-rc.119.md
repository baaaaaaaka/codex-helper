## Why

New chat in the CXP TUI handed an empty, unpersisted thread to Codex `resume`, which could fail with `no rollout found`. Update recovery also mistook valid executable aliases for self-referencing links. Teams prompt receipts could be omitted when pasted conversation text already contained an older receipt.

## What changed

- Let the real Codex TUI create its thread on the helper's shared backend, then bind its native `thread/started` notification before later input and approvals. Release abandoned, unbound conversations and reject the incompatible legacy-helper handoff. Preserve the separate-home fallback.
- Preserve healthy absolute and relative executable symlinks. Attempt `.prev` recovery only after an actual symlink-loop error.
- Identify a Teams prompt receipt by a link to its current chat and message, instead of copied receipt text or HTML comments. Preserve message content, attachments, mentions and code order.
- Require offline contracts with a real helper, CXP selector, Codex TUI and PTY for Codex 0.166.0 and 0.167.1. Cover first input, approval, two windows, a second turn, exit and resume, using local model and Graph servers.
- Add sanitized copied-conversation fixtures and receipt retries after a lost PATCH response, HTML normalization and adapter restart.
- Make the voice E2E fixture hold successful ASR until its request receipt is externally visible, then compare the complete transcript and edit history. This removes an uncontrolled annotation-order race and adds checks for feedback during pending recognition.
- Correct three acceptance-test synchronization assumptions: account for bounded, previously admitted sender workers; wait for actual PTY descendant termination before checking file stability; and wait for the first control-chat read before requesting TUI admission. Keep these checks enabled without changing production pacing or process termination.

## Validation

The original symlink and receipt implementations fail the new regression cases. The original helper fails the real New chat flow with `no rollout found`; the repaired flow passes with both pinned native Codex versions. Focused race tests, affected Windows/Darwin cross-compilation and vet checks also pass.

The corrected write-window test passes repeated race runs and still fails when chat-creation pacing is deliberately removed. A controlled delayed PTY exit reproduces the previous false failure; the corrected test passes 100 race runs and rejects an intentionally surviving descendant. Thread binding passes 100 runs with race detection and coverage. The full isolated Go suite and the Linux CI coverage collector pass.

The persistence review found no new state format, background polling or history scans. New thread ownership adds one bounded binding update; receipt retries avoid another PATCH once the current message's identity link is present. CI and Release results are linked with this candidate.

## Compatibility

This is a prerelease of 0.1.22. Update the CLI and helper together: a new CLI rejects a legacy helper's New chat handoff with an actionable error. Existing persisted threads retain their resume flow. No new database or rollout format is introduced. The previously merged legacy token JSON import fix remains included without another migration layer.

Receipt normalization and retry behavior are covered with a local Graph fixture; preservation of the new identity link by live Teams still needs field validation before stable promotion. This release does not claim to repair Teams client clipboard code-block movement.
