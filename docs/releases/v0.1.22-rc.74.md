## Why

An interrupted first conversion could leave a lease file without a completed database. The next start treated the lease as proof of conversion and opened an empty store, so the original Teams conversations stopped receiving replies. A long-running watchdog could also stay on the previous runtime after an update.

The rc.73 Windows CI caught an additional failure: a sharing violation while replacing the runtime pointer could end the watchdog loop. That candidate was stopped before publication. This candidate keeps the watchdog alive and retries safely.

## What changed

- Select the store anchor first, then prepare the database after acquiring its lease. Resume unfinished conversion, and open the database before publishing the lease.
- Refuse to replace a missing published database with an empty store. Reuse completed conversions even if startup stopped before writing the marker or activating the lease.
- Carry cancellation and ownership into the converter. Check ownership between stages and immediately before publishing the completed database. Cancel startup retries as soon as another owner takes over.
- Make the watchdog follow runtime activation and rollback through the stable launcher before checking helper health. Compare against the binary build version so older launchers without a pinned version marker work too.
- Use one loop error policy for runtime refresh and health checks. Log refresh errors, skip health collection in that iteration, and retry after the normal interval. Failed restarts also retry without allowing the old runtime to judge health.
- Add unit, real-process and black-box E2E coverage. Require the startup gate on Linux, Windows and macOS, repeat the seven critical Linux E2E cases three times, and include CLI race checks. The release workflow reuses the same CI gate.

## Validation

- Local validation passed in the development skill's isolated Docker environment: the complete non-scenario Go suites, all E2E packages, relevant race checks, vet, and all script tests.
- Four legacy fixture combinations cover v0.1.20 and rc.59 in JSON and SQLite-WAL forms. All 168 injected cancellation and ownership failures preserve the old data and recover the original chat and thread bindings.
- Pointer-read and restart-failure recovery tests fail against the rc.73 loop and pass after the error-policy refactor. Native Windows CI holds a DELETE-access handle as pointer replacement does and asserts the actual sharing violation before testing recovery in both launcher contexts. The complete startup CLI selection passed three rounds under the original bash CI shell.
- All seven critical E2E cases passed three consecutive rounds. They cover interrupted retries, a crash during import, takeover while waiting or importing, a missing published database, and watchdog upgrade/rollback through both current and older launcher contexts.
- A deliberate mutation that disables conversion ownership checks makes the real-process E2E fail on unsafe database and marker publication. The protected version passes.
- Replacing the watchdog comparison with the old implementation makes both the legacy unit cases and the real release-binary E2E fail on the unchanged executable.
- Windows amd64 and macOS amd64 CLI/converter test binaries cross-compile with CGO disabled; the final CLI also compiles for macOS arm64. Native platform execution is required by CI for this release commit.
- Warm database-open checks remain about 64 ms with either a 1 KiB or 32 MiB old backup, with unchanged allocation volume. This measurement excludes network and Codex startup.
- Required main CI and release checks run against this exact commit; the release workflow blocks packaging and update-index publication on their required dependencies.

## Compatibility

- The CLI base version remains v0.1.22. This change adds no store schema or protocol version.
- Automatic legacy conversion still supports v0.1.20 and rc.59. Other old store versions retain their existing refusal behavior.
- This prevents new empty-store recovery errors. It does not merge or repair an empty database already published by an older defective version.
- A watchdog binary from before this fix must first be switched to the updated runtime through the managed update/restart flow. Existing old processes do not gain the new refresh logic by changing files alone.
- Real NFS outages, machine power loss, and live Teams delivery were not reproduced locally. The local E2E suites use private state and fake Graph/Codex services.
