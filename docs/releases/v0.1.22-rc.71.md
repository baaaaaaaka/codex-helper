## Why

Teams and the local Codex TUI previously used separate writers for the same session. This could block input from one client while the other client was open. Teams also could not collect answers to native Codex questions.

## What changed

- Share one authenticated native app-server per conversation between Teams and `cxp tui`. Both clients can see new input and progress.
- Ordinary Teams messages now steer the active task. Use `helper queue <prompt>` to request a separate task. Native TUI Enter and Tab keep their native behavior.
- Show synchronous and asynchronous Codex questions as separate messages, with the original question and options, English helper instructions, and an owner notification.
- Answer by quoting the question or sending `helper answer Q<number> <answer>`. Use `helper answer Q<number> --skip` to skip. Unquoted messages keep their normal input behavior.
- Reuse the existing durable queue, sender, notification, transcript, and update-drain paths. Add bounded question storage, indexed lookups, recovery checks, and protection against expired or rebound replies.

## Validation

- The full Go test suite passed in the development skill's isolated Docker harness, including the existing and new black-box Teams scenarios.
- Core and channel race tests, repository-wide vet, the Teams test-directory isolation guard, and cross-platform builds passed locally. Targets include Windows amd64, macOS amd64/arm64, and Linux arm64.
- Native Codex 0.166.0 protocol and production-client contracts passed three rounds against an offline Responses fixture. These cover shared input, native queues, both question types, and replies from another client.
- The question feature adds 38 ordinary tests, seven black-box E2E scenarios, and two native contracts. Coverage includes completion races, pause and drain, cancellation, restart, ambiguous writes, notifications, duplicate events, and full execution slots.
- Performance checks cover an 814 MB history fixture and 10,000 question groups. Unchanged reads do not write rows. A 27.8 MB database migrated to the new schema in about 8 ms with 44 KiB growth; ordinary-input question lookup remained about 15–16 microseconds at 100 and 10,000 groups.
- GitHub CI and Release checks run for this exact release commit. Their final status is available on the repository's Actions page.

## Compatibility

- The CLI base version remains `v0.1.22`. Existing queued requests remain queued after the metadata-only schema migration.
- A TUI without a compatible local helper keeps its standalone launch path. An already open standalone Codex window must close and reopen through `cxp tui` to join the shared backend; existing windows are not taken over.
- Planned helper updates wait for attached TUI windows and native work. A helper crash is not a seamless backend migration.
- Synchronous questions need their original live backend. Orphaned requests expire after restart. Uncertain submissions are not replayed automatically.
- Asynchronous answers use native input semantics. Separate clients can both send answers; there is no global exactly-once guarantee. Skipping an asynchronous question in Teams does not dismiss it in the native TUI.
- Actual Teams device push delivery depends on notification settings. Live Teams accounts, interactive terminal key presses, and native Windows/macOS runtime behavior were not exercised locally; local cross-builds and GitHub platform checks cover the supported build targets.
- Publishing this prerelease does not update or restart an installed Teams helper.
