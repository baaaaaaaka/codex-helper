# v0.1.14-rc.21

## Why this prerelease exists

`v0.1.14-rc.20` fixed the runtime dispatcher so an explicitly selected
same-base prerelease is not replaced by the newer stable version. A remaining
failure was found in the candidate-owned update transaction itself:
candidate verification still executed the stable entrypoint and required its
physical `--version` output to equal the requested prerelease. In a split
installation, the stable entrypoint can legitimately be an older compatibility
launcher while the immutable runtime and `active` pointer already contain the
requested target. That made a successful stable-to-prerelease activation fail
with an error such as:

```text
fresh stable entry version output "cxp version 0.1.14 ..." does not contain v0.1.14-rc.20
```

This candidate separates the authoritative immutable runtime check from the
compatibility-entry check and adds a guard against an old dispatcher silently
moving the active pointer back to stable during verification.

## What changed

- Candidate-owned updates now execute the published immutable runtime directly
  with runtime-dispatch markers disabled and require its exact requested
  version. They no longer use the stable entrypoint's physical version string
  as the candidate success criterion.
- Managed finalization still requires the stable `cxp` entrypoint to be
  runnable from a clean environment. Its physical version may be older than an
  explicitly selected prerelease, but a fresh probe must not change the active
  immutable runtime away from that target.
- If a stable probe attempts to reactivate an older runtime, finalization
  restores the requested active pointer and fails closed instead of reporting a
  successful update that would be undone after restart.
- The candidate-owned smoke test now checks the intended pending-marker order:
  activation leaves the marker for fresh-start recovery, and the next entry
  invocation consumes it. This covers both the first and repeated update.
- The release and platform-integration CI paths explicitly run the stable
  compatibility, unrunnable-entry, and active-pointer regression tests.

## Test and CI coverage

The qualification matrix includes:

- `go test ./... -count=1` and `go test -race ./... -count=1`;
- focused candidate-update, helper-runtime, managed-install, and finalizer
  tests, including the split stable/prerelease case and an old dispatcher that
  rewrites `active`;
- the candidate-owned update smoke with pending-state recovery;
- Docker SSH/SOCKS proxy fault recovery and resource-budget smokes;
- loopback proxy recovery on Ubuntu, macOS, and Windows;
- Windows and macOS cross-compilation of the affected runtime and CLI paths;
- workflow validation with `actionlint` and the release upgrade-compatibility
  matrix.

This is a prerelease and does not replace the existing `v0.1.14` stable
release. It is intended for users who need to validate the managed
stable-to-prerelease update path with `helper update prerelease` or an
explicit version request.
