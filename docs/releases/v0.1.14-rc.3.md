## Why this prerelease exists

Codex users increasingly need official GPT models and organization-hosted, OpenAI-compatible models in the same CLI, desktop app, and Teams workflow. Earlier CXP model profiles were local, static launch presets: they could not safely merge Codex's live official catalog with externally maintained third-party model definitions, verify that credentials actually worked before advertising a model, or preserve a long-running Teams conversation while its model changed.

This prerelease turns model profiles into a verified, externally tunable routing layer while keeping official Codex behavior unchanged when no third-party profiles are configured.

## What changed

### One model catalog, with official models first

- CXP obtains the signed-in Codex account's live official model catalog, including each model's advertised reasoning-effort values and default.
- Verified third-party profiles are merged after official models with explicit `official:` and `profile:` namespaces available for ambiguous names.
- The selected default is shown explicitly. A configured third-party model is hidden until its credential has passed a real provider request.
- If the unified gateway cannot start for an official model, native Codex fallback preserves the exact requested model slug; it never silently substitutes the Codex default.
- Official catalog results are cached briefly to avoid repeated app-server startup while still refreshing changes from Codex.

### Git-managed, externally tunable profiles

- Users can sync JSON profile repositories before entering any secret, then bind one credential to one or many profiles from the same provider.
- Sources refresh automatically every 30 minutes. Valid updates activate without user action; invalid updates preserve the last-known-good snapshot and display an explicit backup-profile warning.
- Git-sourced profiles are reverified automatically when their effective configuration changes. Legacy local profiles remain compatible and do not suddenly disappear after upgrade.
- Provider, model, capability, reasoning, tool-call, streaming, token-limit, cache, retry, and compatibility behavior can be tuned per model without rebuilding CXP.

### Reliable model switching in existing Teams chats

- `model list`, `model status`, `model switch <name>`, and `model fork <name>` now operate on the merged verified catalog.
- A switch during an idle chat starts a fresh model generation immediately. Re-selecting the same runtime is a no-op and preserves the current Codex thread.
- A switch requested while work is queued or running becomes pending instead of interrupting the user. Already captured turns keep their original model, effort, and thread; newly queued turns capture the pending generation; activation occurs at the exact queue boundary.
- Switch and queue operations share one serialization boundary, preventing a turn from being attached to the wrong model generation.
- Explicit reasoning effort is preserved only when supported by the destination model; otherwise it moves to that model's default with a targeted notice. Automatic/default effort changes stay silent.
- Thread journals persist model generation and runtime identity so restart recovery cannot resume a thread against the wrong provider.

### Third-party Responses compatibility

- The adapter supports model-specific reasoning parameters and response fields, sampling suppression, tool-choice restrictions, strict-schema stripping, empty assistant content, tool-call ID/name limits, parallel-tool policy, and stream termination behavior.
- Usage normalization preserves available prompt, completion, reasoning, and cached-input token data without inventing metrics a provider does not return.
- Provider routing, retry classification, SSE assembly, tool history, and request clamping are independently configurable for DeepSeek, GLM, MiniMax, Nemotron, MiMo, and future OpenAI-compatible deployments.
- Models without native web search can delegate a search task to an official GPT subagent; models with native search remain on their native path.

## Compatibility and failure behavior

- With no third-party profiles configured, CXP stays on the native official-model path and existing Codex CLI, app, and Teams behavior is preserved.
- Existing JSON and SQLite session stores remain readable; new optional fields are carried inside version-tolerant JSON records and require no destructive migration.
- Credential values never enter profile repositories, generated catalogs, logs, or model-list output.
- Missing credentials, failed verification, invalid upstream JSON, or an unavailable provider fail closed for that third-party model without hiding signed-in official models.
- Durable session state remains authoritative if the in-memory Teams registry projection cannot be refreshed.

## Review fixes included before tagging

The release review found and corrected several semantic issues beyond the first implementation:

- made pending switches snapshot all later turns to the new generation so a busy chat cannot starve a requested switch;
- persisted pending model and effort state across helper restarts and activated it only at a safe queue boundary;
- serialized queue capture and model switching to eliminate generation races;
- retained exact official model selection during native fallback;
- automatically migrated and reverified sourced profiles while preserving historical local profiles;
- prevented identical-profile switches from discarding conversation continuity;
- preserved generation-aware thread recovery rather than disabling journal recovery after the first switch;
- reset unsupported cross-model effort values predictably and suppressed notices for changes that can be handled safely;
- warned whenever a last-known-good backup JSON is active, including cases where the backup remains usable;
- cached official catalog discovery without caching authentication failures or fabricated model metadata.

- Complete `go test ./...`, `go vet ./...`, `git diff --check`, and actionlint `v1.7.11` validation.
- Focused race tests for concurrent model switching, queue capture, registry projection, and pending-generation activation.
- JSON and SQLite restart/recovery coverage for active and pending model generations, effort snapshots, and thread journals.
- A clean `golang:1.25-bookworm` Docker run of the Teams, CLI, model-profile, and Responses-adapter test suites.
- Windows amd64 cross-compilation of the CLI and `codex-proxy` entrypoints.
- Real regulated-account integration testing through the current official Codex binary: GPT-5.6 Luna to NVIDIA-hosted third-party model and back to GPT-5.6 Luna, verifying model identity, routing, usage fields, and official prompt-cache continuity.
- A gated scheduled GitHub Actions workflow repeats the official-to-NVIDIA-to-official test with repository-managed secrets; ordinary forks and repositories without the opt-in variable skip it safely.
- Release CI adds focused model-catalog, credential verification, adapter, Teams switching, queue-boundary, effort, and recovery contracts across supported runner environments.
