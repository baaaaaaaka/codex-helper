# v0.1.22-rc.84

## Why

Automatic CXP TUI updates must not delay a session when GitHub is slow or
unavailable. A failed or interrupted update must also leave the next startup
able to run the last confirmed version.

## What changed

- Check for updates in the background after the first TUI frame. Shared locks,
  cooldowns, bounded retries, disk-space checks, and opt-out settings keep
  network and storage failures out of startup.
- Keep the stable CLI as a bootstrap and fallback. Download and verify an
  immutable candidate without changing the confirmed version. A later TUI
  startup claims one trial, waits for a local first-frame acknowledgement, and
  falls back to the confirmed version if startup fails. Existing windows are
  not restarted.
- Use a bounded boot record as the only version selector after safe boot starts.
  Failed candidates are not retried automatically. Confirmed startup failures
  can use the retained previous version.
- Add a repository-published manifest that binds the version, platform, boot
  protocol, release priority, asset size, and SHA-256. Publish it only after
  native tests pass on Linux, macOS, and Windows. Release CI runs startup tests
  against the packaged release binaries before publishing the manifest.
- Keep automatic releases within the existing configuration reader contract.
  Explicit upgrades remain available for older launchers and incompatible
  protocol changes.
- Add ordinary, race, process, PTY, publisher, and native CI coverage for
  interrupted downloads, corrupt state, candidate failures, parent termination,
  cancellation, fallback, and terminal recovery.

## Validation

- The complete Go test suite, focused race checks, `go vet`, and the 139-test
  Python script suite pass in the development environment. Nine Python tests
  are platform-skipped.
- Linux native process and PTY tests pass in the isolated development Docker
  harness. The first TUI frame appeared in about 9 ms in that test environment;
  the stable bootstrap used about 12.7 MiB of resident memory.
- Linux amd64, macOS amd64 and arm64, and Windows amd64 CLI builds pass. Native
  macOS and Windows execution is required by the RC release matrix.
- CI runs the same boot-safety gate on Linux, both macOS architectures, and
  Windows 2022 and 2025. Release CI repeats the gate against the packaged bytes.

## Compatibility

The CLI base version remains `v0.1.22`; this release adds boot protocol 1. The
automatic path does not perform irreversible configuration or state migrations.
An older physical launcher defers automatic updates until an explicit install
or upgrade adds protocol support. The stable bootstrap and up to eight immutable
runtime versions are retained; after that limit, automatic downloads defer
instead of deleting runtimes that an open window may still use. The manifest
uses GitHub HTTPS publisher trust and SHA-256 asset binding; it is not an offline
signature.
