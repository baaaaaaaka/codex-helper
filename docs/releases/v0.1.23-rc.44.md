# v0.1.23-rc.44

## Why

An ordinary CLI error such as `cxp version` (a missing profile, rather than the
supported `cxp --version`) could be treated as failure of the confirmed runtime.
The stable bootstrap could replay the command using a retained older executable
and persist that downgrade. That executable might not understand a Teams
database already migrated by the current version.

Some business E2E declarations also overstated their coverage: the explicit-path
Codex update refusal did not exercise a successful managed npm update, and an
idle-settle timeout could leave a successful scenario without an idle check.

## What changed

- Execute a confirmed runtime once and return its result. Ordinary errors and
  crashes cannot select `previous`, replay the command or run the bootstrap's
  embedded CLI. An unavailable confirmed executable produces a startup error.
- Preserve the existing unconfirmed-candidate trial, readiness handshake and
  recovery to the confirmed runtime before handoff.
- Add production CLI regressions with unchanged boot snapshots, subsequent
  version queries and actual current Teams database reads. Add a pinned native
  historical-bootstrap reinstall regression.
- Exercise automatic and manual managed Codex upgrades through real npm,
  executable replacement and helper restart, using a local package registry.
  Also exercise a real failed package download, unchanged old executable and
  subsequent usable work. Failed work still requires an explicit retry.
- Fail normal successful E2Es that never settle. Distinguish checked, waived and
  unobserved invariants, and clarify that catalog links do not prove execution.
- Replace an obsolete SSH host-key retry test with real first-use and repeat
  connections. Require the exact test's JSON pass event in the owning SSH job;
  a skip or empty selection cannot pass that gate.

## Validation

The local validation records are
[`confirmed-runtime-validation-20261116.md`](../confirmed-runtime-validation-20261116.md)
and [`e2e-safety-validation-20261116.md`](../e2e-safety-validation-20261116.md).
Real processes ran inside the development skill's disposable Docker environment.

- The new CLI regression fails with the original dispatcher because the ordinary
  command rewrites boot state, and passes with the fix.
- The complete Linux TUI/update safety entry point passes, including native
  bootstrap, PTY and historical installer checks. Focused unit/race checks pass.
- All three Linux E2E shard entry points pass: 188 passing scenario verdicts,
  across 15 packages. The two opt-in personal-dataset tests were not executed.
- Actual managed npm upgrade success, manual success and download failure pass.
  Real OpenSSH first/repeat connection and negative fixture checks pass.
- Workflow selection/skip guards, catalog/harness unit tests, focused vet and
  whitespace checks pass. Native platform CI and release results are recorded
  on the GitHub runs associated with this tag; cross-compilation alone is not
  treated as native validation.

Confirmed startup adds no business-state reads, scans or writes. It removes the
confirmed-runtime readiness supervisor and rollback mutation. Regression tests
require byte-for-byte unchanged boot records after command and execution errors.

## Compatibility

No database, configuration or boot protocol migration is introduced. Retained
older binaries remain available for explicit recovery, whose data compatibility
must be established by the operator. Automatic candidate recovery is unchanged.

**Deployment requires replacing the physical bootstrap with the platform
installer for this release.** A runtime-only upgrade preserves the old physical
entry and cannot fix its dispatch policy. Do not downgrade the Teams database
or edit boot records as a workaround. Publishing this prerelease does not update
or restart an installed helper.

Managed npm upgrade scenarios exercise the POSIX installer in Linux CI; Windows
explicitly skips those scenarios and has separate native bootstrap gates.
