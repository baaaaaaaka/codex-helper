## Why

Moving or replacing a Codex session file could change its filesystem identity. The Teams mirror then reset its read cursor and could resend messages that had already appeared in the chat.

## What changed

- Persist evidence for the mirror cursor and an open turn. Verify a replacement before resuming at the same position, or at a uniquely identified matching turn boundary.
- Pause an unverified source for review while other threads continue. Release a completed turn's stored final after its result and the obstruction have both aged at least ten seconds. Suppress late progress for that turn.
- Hold queued recovery records from older versions for explicit full-history publication. Keep in-flight and unknown delivery evidence for read-back.
- Retry transient file errors with backoff and perform verification outside the mirror loop.

## Validation

Linux, Windows and macOS CI, including the three end-to-end shards, passed on the pull request. Linux engine, store and transcript race tests passed, as did three focused runs of the backpressure and restart regression.

A rehearsal with an isolated copy of the repaired database and 593 local session files saved all 593 checkpoints without blocking a chat or adding outbox records. An idle polling benchmark over those files measured 1.37–1.40 ms before and 1.44–1.50 ms after, with 1,193 allocations per pass.

One local container E2E run saw an unrelated CMD-EFFORT golden mismatch at a prompt truncation boundary. The same mismatch occurred on the unchanged base. The GitHub pull request E2E checks passed.

## Compatibility

The core SQLite schema advances to version 14. Earlier binaries refuse the upgraded database. Before using an older version, restore a compatible backup. A source whose replacement cannot be verified stays paused until the original file is restored or the user explicitly publishes the reviewed full history.
