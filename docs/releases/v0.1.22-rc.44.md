# v0.1.22-rc.44

## Why

Teams recovery could appear stalled when legacy SQLite/JSON state combined unsupported Graph recovery bounds, stale projections, and owner-bound queued rows.

## What changed

- Use Graph-supported exclusive `gt`/`lt` recovery bounds with durable overlap and safe head/gap continuation provenance.
- Defer optional history/linked maintenance durably while a Teams backlog is active, with bounded owner-fenced fairness quanta and restart-safe cursors.
- Isolate malformed SQLite rows, bound/keyset backfills, bootstrap legacy empty runtime projections once, preserve opaque terminal turn evidence, and make full rewrites cancellation-aware.
- Fence unscoped queued-turn claims from positive-generation owner rows and keep JSON/SQLite behavior aligned.
- Add strict no-token, network-isolated real-data Docker replay diagnostics and broad manifest/Release regression selectors.
- Stabilize only the race-test harness around multi-step SQLite/recovery observations; production phase, worker, lease, and safety limits are unchanged.

## Validation

- `go test ./... -count=1 -timeout=30m`
- `go test -race ./internal/teams/... -count=1 -timeout=30m`
- `go vet ./internal/teams/...`
- Focused Release selectors: 10 SQLite row-level tests and 22 Teams backlog/frontier tests.
- Teams recovery manifest selector/list validation and a complete isolated manifest run.
- Real-data Docker replay with a copied fixture, fake token/Graph/executor, and `--network none`; the latest changing-source diagnostic made durable progress but did not meet the 100-completion throughput gate.
- Hosted race follow-up: the backlog-gate, current-state replay, and inbound-to-executor task/prompt race tests use production budgets plus bounded test-only multi-step observation windows; the two large SQLite fairness selectors, the inbound race selectors, and the SQLite/WAL recovery selectors use finite test watchdogs up to 120 seconds.
- Hosted Windows follow-up: the Graph-head-failure listener assertion now allows finite startup scheduling margin, and the stale-transcript async test explicitly performs the local Accepted-to-Sent reconciliation after the worker completes. These are test-only observations; production timeouts, retries, Graph behavior, and durable safety boundaries are unchanged.

## Compatibility

Existing JSON and SQLite stores remain readable. Mixed-version scalar projections remain compatibility fallbacks while canonical JSON remains authoritative. Unknown Graph POST outcomes are never automatically resent; owner/lease/attempt/frontier CAS and separate ACK/marker/final durability boundaries remain unchanged. The Docker diagnostic never mounts auth tokens or writes the live store.
