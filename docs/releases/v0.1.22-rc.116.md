## Why

New chat in the CXP TUI handed an empty, unpersisted thread to Codex `resume`, which could fail with `no rollout found`. Update recovery also mistook valid executable aliases for self-referencing links. Teams prompt receipts could be omitted when pasted conversation text already contained an older receipt.

## What changed

The previous RC attempt exposed an existing nightly assertion that compared token admission with asynchronous worker start times. This candidate accounts for the configured number of previously admitted workers, retains the race test and validates that removing chat-creation pacing still fails it. No rate limit or production sender behavior is changed.

- Let the real Codex TUI create a new thread on the helper's shared backend, then bind its native `thread/started` notification before later input and approvals. Release abandoned, unbound conversations and reject the incompatible legacy-helper handoff.
- Preserve healthy absolute and relative executable symlinks. Attempt `.prev` recovery only after an actual symlink-loop error.
- Identify a Teams prompt receipt by a link to its current chat and message, rather than matching copied receipt text or relying on HTML comments. Preserve message content, attachments, mentions and code order.
- Add offline tests using a real helper, CXP selector, Codex TUI, PTY and local model/Graph servers. Cover first input, approval, two windows, a second turn, exit and resume. Make native contracts required for Codex 0.166.0 and 0.167.1 in CI and the release pipeline.
- Add sanitized copied-conversation fixtures and regression coverage for receipt retries after a lost PATCH response, HTML normalization and adapter restart.

## Validation

The original symlink and copied-receipt implementations fail the new regression cases. The original helper fails the real New chat flow with `no rollout found`; the repaired flow passes with both native Codex versions. Focused race tests, affected Windows/Darwin cross-compilation and vet checks also pass. The final synchronized source is checked by the full Go suite and the required CI and Release workflows.

The persistence review found no new state format, background polling or history scans. New thread ownership adds one bounded binding update; receipt retries read the target message and avoid a further PATCH once its identity link is present.

## Compatibility

This is a prerelease of 0.1.22. Update the CLI and helper together: a new CLI rejects a legacy helper's New chat handoff with an actionable error. Existing persisted threads retain their resume flow. No new database or rollout format is introduced.

Receipt normalization and retry behavior are covered with a local Graph fixture; preservation of the new identity link by live Teams still needs field validation. This release does not claim to repair Teams client clipboard code-block movement. The previously merged legacy token JSON import fix remains included without another migration layer.
