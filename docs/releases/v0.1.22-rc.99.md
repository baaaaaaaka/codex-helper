# SQLite-only state cutover

## Why

Small updates to growing JSON state required full-object decoding and rewriting,
including JSON stored inside SQLite. Unconfirmed message delivery could also
keep completion notices in a growing collection and block later work.

## What changed

- CXP-owned business state now uses concrete SQLite columns and ordered child
  tables: core state, attachments and quotes, delegation, configuration,
  credentials, skills, registry, gateway, service and process identities, and
  install/update records. Legacy decoders run only at migration boundaries.
- Point operations, reusable connections, atomic parent/child changes, bounded
  notification queries and same-value suppression replace whole-object saves.
  Unknown delivery keeps its content and attempt identity while later work can
  continue; the helper does not blindly repeat an uncertain POST.
- Boot protocol 2 uses native immutable SQLite snapshots. CLI handoffs use a
  separate SQLite mailbox. The lease retains its ownership algorithm and fixed
  slots, with explicit binary fields. Obsolete legacy runtime repair paths are
  removed; there is no dual storage backend or generic conversion framework.

## Validation

Local checks use synthetic state and ephemeral Docker for real lifecycle tests.
They cover the full Go suite, core and selected persistence race tests, repeated
critical migration/crash/notification E2E, candidate install/update/recovery,
TUI/PTY, supervisor and skills migration. Native Windows tests cover SQLite,
publication, bootstrap, missing state and delegation retention. CI additionally
requires native macOS, real NFS and checksum-verified old/current release
artifact cutover checks. Check the linked release workflow for their results;
cross compilation alone does not establish those contracts. Installer, systemd
handoff and process-identity fixtures use native boot/install records. Native
Windows tests also check connection cleanup and shared-handle PID writes;
independent openers remain covered. Build caches stay outside synthetic accounts,
and activity-clock tests use advancing time under race instrumentation. Bootstrap
reads preserve native sharing errors so the Windows watchdog can retry them;
lost published state remains a fatal error rather than a new installation.
Unix process-identity checks and frozen watchdog fixtures use native immutable
boot publication without rewriting its seal.

Linux fixtures at 1 / 1,000 / 100,000 history rows confirm no mutation syscalls
for read-only or same-value config operations. At every scale, 100 heartbeats
use about 3.33 MB of pwrite calls and 300 sync calls; 100 settings edits use
about 1.69 MB and 300 sync calls. A strict delegation retention seek removes
repeated scans of empty legacy timestamps: one measured 100-chain workload
improved from 3.48 s to about 0.42 s. Twenty fresh native version/config-list
processes take about 121/137 ms total with no state rewrites. These are workload
observations, not latency guarantees. Unknown-send reconciliation still has
proportional Graph read-back work.

## Compatibility

**This is a one-way storage change. Stop or isolate old writers, take a
consistent backup, then use the explicit installer.** Historical updaters
refuse this candidate before replacement. Boot protocol 2, core schema 6,
delegation schema 2 and config reader floor 7 prevent incompatible runtime
selection. The installer drops protocol-one rollback/trial targets. A missing
or corrupt published database stops startup; it never falls back to JSON or
silently recreates empty business state.

Backups must include committed WAL data. After new writes begin, downgrade
requires stopping the new writers and restoring the matching old state and
executable together; restoring only an old executable is unsupported.

First migration needs working memory and temporary disk space. In synthetic
100,000-record fixtures, sampled directory peaks are about 391 MB for core and
493 MB for delegation, excluding backups. These are lower bounds, not capacity
ceilings. The old 108 MB core JSON value is materialized once and reaches about
352 MiB process high-water RSS; row-wise delegation conversion uses about
22 MiB. No automatic full VACUUM follows migration.

External Graph/OAuth/delegation protocols, command `--json` output and Codex-owned
formats keep their encodings. Production installation and service activation
are separate operator actions; this release does not restart an existing helper.
