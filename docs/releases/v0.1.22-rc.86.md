# v0.1.22-rc.86

## Why

The candidate updater must compare normalized versions because callers may
provide a target without the `v` prefix. The RC85 release checks also exposed
a supervisor test fixture whose fixed process ID could match the test runner.

## What changed

- Normalize the requested candidate version before comparing it with the
  immutable runtime's reported version, and reject invalid targets before
  probing.
- Exercise candidate apply with the unprefixed version format used by the
  production updater.
- Use a process ID distinct from the runner in the supervisor adoption test.

## Validation

- `go test ./internal/candidateupdate ./internal/update` passes.
- `go test ./internal/cli -run '^TestProxySupervisorAdoptsExistingDaemonBeforeStartingChild$' -count=25` passes.
- `git diff --check` passes.
- Main CI and the release workflow validate this prerelease across supported
  platforms.

## Compatibility

Prefixed and unprefixed semantic versions remain supported. The supervisor
change is limited to its test fixture; no update protocol or persisted state
format changes.
