# v0.1.22-rc.22

## Why

Opening a large legacy Codex conversation through `cxp resume <thread-id>` in
the remote TUI could fail before the TUI became usable. The official Codex
history migration needs to happen before the remote broker starts reading the
app-server stream, so the legacy conversation is not requested as one
oversized `thread/read` response.

## What changed

- Run the official Codex rollout migration as a hidden preflight for an
  explicit canonical-thread `resume` and for session-specific TUI launches.
- Start the remote broker only after migration reports a verified target
  outcome; reject missing, ambiguous, failed, or invalid migration reports
  without starting a partial TUI session.
- Keep the raw legacy JSONL file untouched and preserve the existing behavior
  for new TUI sessions, preview/list, fork, Teams, `--last`, and named resume
  invocations.
- Keep migration process output bounded and isolated from broker credentials,
  while controlling cancellation and child-process cleanup.
- Add coverage for invocation routing, broker ordering, report validation,
  environment isolation, failure handling, cancellation, and process-group
  cleanup.

## Validation

- `go test ./... -count=1`
- `go test ./internal/cli -count=1`
- `go test ./internal/codexhistory ./internal/codexrunner -count=1`
- `go vet ./internal/cli ./internal/codexhistory ./internal/codexrunner`
- `gofmt -l` on all changed Go files
- `git diff --check`

The live end-to-end wire test against an installed Codex and a real oversized
legacy rollout remains a follow-up validation; this CXP release does not
modify or bundle the official Codex repository.

## Compatibility

This change requires an official Codex build that provides the
`migrate-rollouts --apply --thread <id> --json` command. CXP does not modify
Codex, the remote broker protocol, or the Teams service. Raw legacy history is
not rewritten by CXP, and existing Teams metadata-only resume behavior is
unchanged. If migration cannot produce a verified result, CXP fails before
opening the broker instead of risking a partial or duplicate session.
