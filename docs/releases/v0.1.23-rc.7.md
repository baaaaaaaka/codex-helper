# Per-chat automatic park policy

## Why

Some Teams work chats need to stay available after long idle periods. Previously,
the helper automatically parked every eligible work chat after 48 hours, stopping
its direct reads until it woke again.

## What changed

- Set or inspect automatic park with `helper park on|off|status` in a work chat,
  `park <session> on|off|status` in the control chat, or `cxp teams service park
  <session> on|off|status` in a terminal. Work chats default to on; off persists
  across helper restarts and chat recreation. A new fork defaults to on.
- Manual park remains available. Changing the setting does not wake a parked or
  held chat or keep a Codex process running. Resume a parked chat from control
  with `r <session>`.
- Direct reads use 2, 5, 10 and 30 second cooling tiers. A running request stays
  at 2 seconds; control chat remains at 5 seconds. An active chat with automatic
  park off continues at the cold tier after 48 hours. Scans may trigger earlier
  reads; account pacing and error backoff can delay the target interval.
- Periodic reads of idle work chats can be more frequent than the previous
  ten-minute scan safety reads, and grow with the number of eligible chats.
  The account-wide read budget remains unchanged.
- Preserve the existing shared read limiter and scheduling jitter. Show the
  policy in session status, details and control lists.

## Validation

The change includes migration, default, persistence, rollback, command,
maintenance, concurrency and polling boundary regression tests. Linux race
checks cover the store, engine and migration packages. Isolated real-process
scenarios cover lifecycle, commands, dashboard, chats, edits, faults and legacy
migration using fake Graph and fake Codex endpoints. Native Windows execution and
live Graph limits were not measured locally. The 10,000-chat interval benchmark
made no allocations and added no database reads to the polling path. Detailed
results are in the repository validation record.

Publication is subject to the main CI and the complete Release workflow,
including native-platform preflights and packaged update tests.

## Compatibility

Schema version 8 adds a default-on policy field without rewriting conversation
history. Older helpers that do not understand this schema may not open an
upgraded store. Existing and new work chats default to on until explicitly set
off. These changes take effect when the updated helper runs.
