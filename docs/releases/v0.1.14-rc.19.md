# v0.1.14-rc.19

## Why this prerelease exists

Users can return from a macOS lid-close/sleep cycle or a Windows network
transition with the local HTTP proxy process still alive while its SSH/SOCKS
backend is no longer usable. The old lifecycle also made recovery vulnerable
to duplicate starts, stale daemon cleanup, orphaned child processes, leaked
CONNECT tunnels, and retry accounting that could be reset when a supervisor
restarted. A local health endpoint or an unchanged port was not sufficient
evidence that the real route was still working.

This prerelease makes recovery a bounded, observable lifecycle rather than an
unbounded restart loop. It is intended to make network loss and resume
recoverable without adding steady-state request, port, or process storms.

## What changed

- Kept the external HTTP listener stable while routing through replaceable
  backend generations. A candidate SSH/SOCKS backend is probed before it can
  replace the active generation; candidate failure leaves a working active
  backend untouched.
- Added request-failure and network-resume probes with single-flight
  coalescing, bounded confirmation and restart budgets, durable blocked state,
  and monotonic merging when daemon and supervisor writers update the same
  budget concurrently.
- Fenced late generation dials, bounded old-connection draining, and force
  closed active hijacked CONNECT tunnels during shutdown so recovery cannot
  leave handlers, sockets, or goroutines behind.
- Added broker identity/epoch and owner-token checks, startup serialization,
  owner-fenced cleanup, replacement-owner stop protection, and PID command-line
  validation to avoid killing an unrelated process after PID reuse.
- Hardened Unix process-group and Windows Job Object cleanup and supervisor
  signal handling. Supervisor adoption now verifies that an existing PID is a
  proxy process before waiting on it.
- Added real proxy-chain loop/hop-limit and DNS-alias matrices, including IPv4,
  IPv6, wildcard listener, trailing-dot, and unresolved-alias cases.
- Added explicit CI fault labs for Ubuntu, macOS, and Windows loopback paths;
  Docker SSH/SOCKS network reset, network rebuild, and 100% packet-loss paths;
  short resource-budget checks; and native supervisor/process validation.

## Validation performed for this prerelease

- `go test ./... -count=1`
- `go test -race ./internal/localproxy ./internal/cli ./internal/manager ./internal/ssh ./internal/stack -count=1`
- Windows and macOS amd64 cross-compilation of the core proxy packages
- `go run github.com/rhysd/actionlint/cmd/actionlint@v1.7.11 -color`
- `bash scripts/ci/proxy_recovery_docker_smoke.sh`

The final Docker run exercised SSH peer restart, Docker network rebuild,
100%-loss injection, recovery/reconnect, concurrent CONNECT traffic, and
cleanup. Its healthy steady-state workload completed with 4,768 successful
CONNECTs and 0 failures in about two seconds (about 2,378 requests/second),
with one generation, zero recoveries, and zero backend failures. The short
resource test settled at two goroutines and seven file descriptors after
repeated start/close cycles.

## CI boundary

Hosted GitHub runners can deterministically reproduce the transport failures,
resume notification, generation swap, route probe, process cleanup, and
resource-budget behaviors. They cannot physically close a laptop lid or
hibernate the host. The native workflow therefore keeps installed Edge and
WSL2 checks availability-gated; when those facilities are present it performs
real effective-proxy/raw-connect checks, while the deterministic loopback and
Docker jobs remain the required regression coverage.
