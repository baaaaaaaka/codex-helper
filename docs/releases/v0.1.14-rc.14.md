## Why this prerelease exists

Teams previously exposed a model-profile switch that could report success without reliably changing the model sent in the next Codex `turn/start`. The switch also advanced the profile generation by discarding the active Codex thread ID, so a change such as an official GPT model to another official GPT model created a new conversation and lost the working context from the user's point of view. Provider-family transitions added another constraint: portable user, assistant, and tool history must survive, while opaque third-party reasoning items must not be replayed to the official Responses endpoint.

The earlier tests checked profile resolution, gateway routing, session snapshots, and runner replacement as separate units. They did not drive the production Teams executor through an installed Codex app-server and assert all of the following at once: the exact per-turn model, the exact effort, stable thread identity, visible-history completeness, and safe history conversion across provider families. That gap allowed the UI/session state to look correct while the effective request still inherited another model.

This candidate makes model and effort selection explicit per turn, preserves one Codex thread across compatible runner generations, and adds an actual-binary contract that verifies the complete boundary without using any real account credential.

## Command and configuration model

- `model` and `effort` now affect only the chat where the command is sent. Both commands work in Work and Control chats.
- `default` is an extensible, Control-only global-default command. It affects future launches and newly created chats under the same CXP config root; it never mutates existing chats, including the Control chat that issued it.
- Registered commands include `default status`, `default model status|list|set|reset`, and `default effort status|list|set|reset`. The registry owns help, aliases, unknown-setting diagnostics, and future default-setting expansion.
- Global defaults are persisted in a typed `GlobalDefaults` container. Legacy `defaultModelProfile` remains readable and is migrated without changing existing-installation fallback behavior.
- `default model set default` retains the dynamic official account default instead of freezing today's resolved GPT slug.
- Model and effort are validated and written atomically. An unsupported explicit effort is retained when valid, otherwise changed to the target model's advertised default with a visible notice. Missing or inconsistent catalogs fail closed without partially modifying the configuration.
- Concurrent selector or profile-capability edits are detected inside the locked config update. The command asks the operator to retry instead of persisting a value validated against a stale model profile.
- Model setup and credential intake only make a profile available; they no longer change either the current chat or global defaults as an implicit side effect.

## Context-preserving model and effort routing

- Every Teams turn now sends the selected public model through the app-server `turn/start.model` field and the selected reasoning effort through its per-turn effort field. The persisted Codex `turn_context` therefore records the effective values, not merely the Teams-side intent.
- A model switch creates a new runner generation when required but keeps the existing Codex thread ID. Returning to an earlier provider uses a fresh generation runner while resuming the same thread, avoiding stale process state without sacrificing conversation history.
- Generation-aware runner caching and reclamation prevent an old provider process from being reused after a switch and close superseded session runners deterministically.
- New chats inherit typed global model and effort defaults. Existing and already-pinned chats do not re-inherit later global changes.
- Native official launches preserve the user's normal Codex provider/catalog/search settings when only effort is overridden. An explicit official model selection removes stale third-party model/provider/catalog overrides before launch.
- Official catalog resolution rejects an unavailable `gpt-*` slug when the account catalog was retrieved successfully, preventing a typo from being accepted as an apparent official model.
- The unified gateway removes adapter-generated third-party reasoning items before a request returns to an official model. In the other direction it removes official opaque `encrypted_content` before third-party routing while retaining visible reasoning summaries. Both directions preserve portable user, assistant, and tool history.

## Credential-free CI and release safety

- Delete the three repository workflows that accepted external OpenAI, NVIDIA, proxy, Teams, or file-write credential inputs: `model-routing-live.yml`, `codex-live-cloud-config.yml`, and `teams-live-lossless-edit.yml`.
- Repository settings were audited before release: there are no GitHub Actions secrets, Actions variables, or GitHub environments configured for this repository.
- Repository workflows no longer reference `${{ secrets.* }}`. Release publication uses only GitHub's ephemeral, job-scoped `${{ github.token }}` with repository-scoped permissions.
- CI now fails if any workflow adds a `secrets.*` expression or one of the removed external credential inputs. This turns the no-real-token requirement into a maintained repository invariant.
- The cross-platform runtime contract still installs and launches the original Codex binary. It creates a fresh temporary `CODEX_HOME`, synthetic ChatGPT auth metadata, and local loopback official and NVIDIA-like Responses services; no OpenAI, NVIDIA, Teams, or proxy account token is stored or injected.
- The synthetic actual-binary route performs official Sol -> NVIDIA-like Nemotron -> official Luna in one thread. It asserts exact per-turn model and effort, unchanged thread ID, retention of the unique user marker and both prior visible assistant answers, removal of third-party private reasoning, and the exact three persisted `turn_context` records.
- The runtime contract matrix covers Linux, macOS, and Windows with both the minimum supported Codex `0.131.0` and current `latest`. Release preflight and main CI also run targeted global-default, runner-generation, history-sanitization, and command-scope tests on every supported runner OS.

## Additional review corrections

- Validate persisted global model selectors and reasoning-effort strings during config load/save, including dangling profile selectors and malformed or oversized effort values.
- Repair typed default profile references independently from the legacy compatibility field when a model source is removed.
- Preserve the advertised model default effort for new chats only when a typed global model was explicitly selected; legacy configurations continue to inherit the runtime fallback.
- Report default status sources accurately as explicit, model default, legacy fallback, or inherited runtime behavior.
- Preserve future official encrypted reasoning items even when they carry content, while continuing to reject adapter-owned `rs_resp_*` reasoning artifacts.
- Keep Control and Work chat behavior aligned for chat-local model and effort changes, including active-turn serialization, queued-turn generation pinning, reset behavior, help text, and user-facing scope notices.
