# Safe ChatGPT desktop migration and deterministic release qualification

This prerelease supersedes `v0.1.13-rc.59`. It carries the same desktop entry
compatibility change and also removes an unrelated wall-clock assumption that
made the Windows full-suite qualification flaky under a loaded GitHub runner.

## Desktop entry migration

OpenAI's current macOS distribution exposes Codex through `ChatGPT.app` and the
`ChatGPT` executable, while older installations use `Codex.app` and `Codex`.
Windows retains the `OpenAI.Codex` Store package identity but package manifests
can expose `ChatGPT.exe` or the legacy `Codex.exe`.

The helper now follows the current entry without abandoning old packages:

- macOS prefers the Codex-capable `ChatGPT.app` entry and falls back to
  `Codex.app`. Transitional bundles can use either executable name.
- macOS requires the exact bundle identifier `com.openai.codex`, OpenAI Team ID
  `2DC432GLL2`, a strict valid signature, and a successful Gatekeeper assessment.
- A classic `ChatGPT.app` is never mistaken for Codex or overwritten. A name
  collision falls back safely to `Codex.app`; two non-Codex conflicts fail
  closed.
- Windows obtains executable paths and AppX entries from the package manifest,
  preferring `ChatGPT.exe` and then `Codex.exe`.
- A single unknown AppX entry remains a conservative compatibility fallback,
  while ambiguous unknown entries are rejected instead of launching an
  unrelated application.
- Store product ID `9PLM9XGG6VKS` and package identity `OpenAI.Codex` are
  unchanged, preserving install and update continuity.

New and old entries can coexist. Selection is deterministic, a broken current
entry does not hide a valid legacy installation, and legacy `Codex.app`,
`Codex`, and `Codex.exe` paths remain supported.

## Why rc.60 replaces rc.59

The `v0.1.13-rc.59` main CI run reached a pre-existing Teams Graph pacing test
failure on Windows. Production correctly requested one positive same-chat
pacing sleep of about 516 ms. The test nevertheless required at least 600 ms
because it assumed all outbox queue and flush setup would always finish in less
than half of the 1.2-second pacing interval.

That lower bound was not a production contract: elapsed setup time must reduce
the remaining sleep. The test still requires exactly one pacing sleep and
requires it to be positive and no greater than the configured interval, but no
longer fails merely because a loaded runner spent legitimate time before the
pacing calculation.

The corrected test passes 100 consecutive runs on Linux and 100 consecutive
runs as a native Windows test executable before this replacement tag is
created.

## Coverage and release gates

- Unit tests cover current-only, legacy-only, coexistence, mixed executable
  layouts, broken-current fallback, exact macOS identity parsing, classic
  ChatGPT collisions, safe alternate-name installation, and conflict refusal.
- Windows PowerShell integration tests execute current-first, legacy-only,
  single-unknown, ambiguous multi-entry, and nonstandard manifest-path cases.
- macOS network-install CI downloads the current official DMG, verifies its
  exact identity, requires the ChatGPT entry, and observes the launched process.
- Windows network-install CI installs the real Store package, verifies its
  manifest and executable, and observes either supported process name.
- Qualification includes the full Go suite, Windows amd64 builds, host Windows
  integration tests, Shell and PowerShell parsing, pinned Actionlint, formatting
  and diff checks, every main CI job, every prerelease job and install smoke,
  and the final release pipeline on the exact same validated commit.
