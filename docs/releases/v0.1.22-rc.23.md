# v0.1.22-rc.23

## Why

The `v0.1.22-rc.22` main CI run exposed a portability race in the new
legacy-rollout migration cleanup test. On Linux, a terminated descendant can
briefly remain as a zombie while no longer executing; the test treated that
state as a live leaked process and failed both coverage and race validation.

## What changed

- Make the process-group cleanup regression use CXP's existing cross-platform
  `proc.IsAlive` definition, which treats Linux zombies as terminated.
- Wait briefly for a genuinely live descendant to exit before reporting a
  process-group leak, while retaining a forced cleanup on a real leak.
- Keep the production migration, broker ordering, and raw legacy history
  behavior unchanged.

## Validation

- `go test -timeout=20m -parallel=16 -coverprofile=/dev/null ./...`
- Repeated process-group cleanup test (`-count=20`)
- Targeted `go test -race ./internal/cli` process-group cleanup test
- `go test ./... -count=1`
- `go vet ./...`
- `gofmt` and `git diff --check`

## Compatibility

This is a test-correctness follow-up to the legacy-history preflight fix. No
Codex source, broker protocol, Teams state, persisted history format, or
runtime migration behavior is changed. The raw legacy rollout remains
untouched and CXP still requires the official Codex `migrate-rollouts` command
for the hidden preflight.
