# Teams cancellation handoff reliability

This prerelease fixes a lifecycle mismatch between Teams and Codex app-server turns. A Teams turn could be marked canceled locally while the corresponding Codex turn was still active, allowing the helper to believe the conversation had finished even though Codex still owned the thread. A later prompt on the same conversation could then conflict with the old turn or leave the Work chat appearing stuck.

## What changed

- Teams now distinguishes an explicit user or supersession cancellation from ordinary helper lifecycle cancellation by attaching a dedicated cancellation cause.
- When an exact Codex turn ID is known, the app-server runner sends `turn/interrupt` for that precise thread and turn.
- An interrupt acknowledgement alone is not treated as completion. The runner waits for the matching terminal turn notification and falls back to a fail-closed thread-state check only when the notification path cannot confirm termination.
- Same-thread requests remain serialized behind a transport-local cancellation fence until the previous turn is confirmed terminal or the thread is confirmed idle. Other Codex threads continue to run independently.
- If cancellation races with `turn/start`, the runner waits for the exact start response. A rejected start preserves the original Codex error; an unconfirmed start is reported as ambiguous and is never retried automatically.
- Empty cancellation gates are now reclaimed atomically with their reference count so rare same-thread recovery races cannot retain stale in-memory entries.

## Safety and compatibility

- Normal long-running turns do not receive a new wall-clock timeout. The bounded confirmation windows run only after an explicit cancellation request.
- Helper shutdown or lost parent context does not masquerade as a user interrupt.
- No Teams store schema, session record, Codex thread ID, or transcript format changed. Conversations created by earlier helper versions continue through the existing metadata-only resume path.
- Uncertain cancellation remains fail-closed: the helper refuses to start duplicate work on the same thread and asks the user to retry later instead of guessing.
- Beacon and non-app-server executors continue to observe standard context cancellation behavior.

## Validation added

- Deterministic concurrency tests cover normal cancellation, cancellation during `turn/start`, interrupt acknowledgement before terminal notification, wrong-turn and wrong-thread notifications, completion races, failed interrupt recovery, unknown turn IDs, persistent fences, lifecycle cancellation, and unrelated-thread progress.
- Teams bridge and executor tests cover explicit cancellation-cause propagation and ambiguous unidentified starts.
- A real installed-Codex contract cancels an active provider request, verifies exact IDs, resumes the same thread, completes a second turn, and confirms the thread returns to idle.
- Main CI runs the real contract on Linux, macOS, and Windows against both Codex `0.131.0` and the latest release. Codex Release Monitor also runs it across tracked Codex versions and the CentOS 7, Rocky Linux 8, and Ubuntu 20.04 container matrix.
- Release preflight runs the focused handoff regression suite on every release platform, while the normal full-suite and race jobs continue to cover the shared runtime.
