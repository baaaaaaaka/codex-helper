# v0.1.13: safe ChatGPT desktop entry migration

This release makes the Codex desktop launcher compatible with OpenAI's unified
ChatGPT desktop entry while deliberately retaining the legacy Codex entry.
Current macOS distributions use `ChatGPT.app` and the `ChatGPT` executable;
older installations use `Codex.app` and `Codex`. Windows keeps the
`OpenAI.Codex` Store identity but can expose `ChatGPT.exe` or `Codex.exe` through
its package manifest.

## Why this release is needed

The previous launcher hard-coded the legacy names. A current package could be
installed successfully but then fail discovery or launch. A simple rename was
not sufficient because a classic ChatGPT installation can also occupy
`ChatGPT.app`, and a Windows package can contain multiple application entries or
place its executable outside the old fixed path.

## Desktop compatibility

- macOS prefers the Codex-capable `ChatGPT.app` entry and falls back to
  `Codex.app`; both current and legacy executable names remain supported.
- Windows derives executable paths and AppX activation entries from the package
  manifest, preferring `ChatGPT.exe` and then `Codex.exe`.
- The existing Microsoft Store product ID `9PLM9XGG6VKS` and package identity
  `OpenAI.Codex` remain unchanged for installation and update compatibility.
- New and old entries can coexist. Selection is deterministic, and a broken
  current entry does not prevent use of a valid legacy installation.

## Safety guarantees

- macOS requires the exact Codex bundle identifier `com.openai.codex`, OpenAI
  Team ID `2DC432GLL2`, a valid strict signature, and a successful Gatekeeper
  assessment.
- A separately installed classic `ChatGPT.app` is not mistaken for Codex and is
  never overwritten. The installer uses `Codex.app` when that name is safely
  available and fails closed if both supported names belong to other apps.
- Windows AppX fallback selects only a `ChatGPT.exe` or `Codex.exe` manifest
  entry. A single unknown entry is retained as a conservative compatibility
  fallback; ambiguous unknown entries are rejected.
- Proxy launches continue to reject fallbacks that would discard required
  Chromium proxy arguments.

## Test and CI coverage

- The regression matrix covers current, legacy, coexistence, mixed executable
  layouts, invalid current entries, classic ChatGPT collisions, exact macOS
  identity parsing, manifest-relative Windows paths, and ambiguous AppX entries.
- Host Windows PowerShell integration tests execute the generated launcher
  selection code rather than checking strings alone.
- macOS CI downloads, verifies, installs, and launches the current official DMG.
- Windows CI installs the actual Store package, checks its manifest and
  executable, and observes either supported process name.
- Release qualification includes the full Go suite, Windows amd64 builds,
  Shell and PowerShell parsing, pinned Actionlint, formatting and diff checks,
  all main-branch CI jobs, all prerelease jobs and install smokes, and the final
  release pipeline on the exact same validated commit.

The legacy `Codex.app`, `Codex`, and `Codex.exe` paths remain supported. This is
a compatibility expansion, not a forced migration.
