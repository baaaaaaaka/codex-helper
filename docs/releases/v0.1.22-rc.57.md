## Why

Make the Windows app-install CI exercise the same supported non-elevated path as users. GitHub-hosted Windows jobs run with an elevated token, so the new production safety guard correctly refused their installation smokes and exposed tests that depended on the runner's ambient token.

## What changed

- Make CLI test hooks report a deterministic non-elevated token by default; elevation-specific regressions continue to override the hook explicitly.
- Run Windows Store and CXP-managed app installation smokes as a temporary standard local user with its own loaded profile. Keep the production elevation checks enabled, and remove the temporary account and files after the smoke.
- Build the managed smoke fixtures before changing identities and pass them into the standard-user run.

## Validation

- Focused app-upgrade and elevation tests, Windows/amd64 test-binary cross-compilation, PowerShell parser checks for the Windows smoke scripts, and `git diff --check` passed locally.
- The 32-test CI shard-contract suite verifies the Windows smoke jobs use the standard-user runner; the full `internal/cli` suite remains blocked locally by WSL-to-Windows PowerShell interop (`UtilBindVsockAnyPort`).
- Require the new GitHub Windows jobs to pass before considering the standard-user install smoke validated.

## Compatibility

- No production elevation policy changes: native Windows install and upgrade still refuse elevated or unverifiable tokens; WSL and other platforms are unchanged.
- This CI correction does not resolve AppX package-identity startup failures or Windows Defender reputation reports. macOS same-bundle LaunchServices forwarding and OpenAI background-updater writes remain unverified; the accepted upgrade procedure still requires quitting all app instances and not reopening from Finder during the update.
