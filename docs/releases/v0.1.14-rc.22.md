# v0.1.14-rc.22

## Why

External provider catalogs are now used to describe DeepSeek/MiMo model
families without baking provider-specific models or credentials into CXP. The
recent catalog-v2 work exposed several correctness risks: ordinary chat could
inherit a feature-only interface, repeated syncs could invalidate an unchanged
profile and its cache identity, provider setup could verify only the default
wire surface, and unsupported structured output could be silently discarded.

## What changed

- Keep `provider/model` selectors stable while allowing each JSON-declared
  operation or native search feature to select its own named interface,
  credential, endpoint, and compiled adapter.
- Reject ambiguous operation routes that map the same operation to different
  interfaces instead of relying on Go map iteration order.
- Verify every interface actually used by a provider's models, including
  DeepSeek Anthropic/Beta routes, through the same adapter factory used at
  runtime. Missing alternate-interface credentials keep the provider hidden.
- Preserve materialized profiles, verification proofs, revisions, and cache
  identity during a no-op catalog sync; rebuild them only when canonical JSON
  content changes.
- Make Anthropic and DeepSeek Beta converters fail explicitly for unsupported
  structured-output/FIM combinations, and harden native web-search detection
  so an ordinary function name or schema cannot trigger a search route.
- Expand CI selectors and the credential-free Docker contract tests so the
  JSON/catalog, routing, adapter, provider-setup, and loopback HTTP regressions
  are actually executed rather than merely present in the repository.
- Validate catalog-relative paths with both POSIX and Windows separators so
  an absolute or traversal path cannot pass validation on the other platform.
- Restore executable bits for every Linux distro smoke test binary after
  artifact download, and wait for the delegation worker before its temp
  directory is cleaned up, keeping the expanded CI matrix deterministic.

## Validation

- `go test ./... -count=1`
- `go test -race ./internal/config ./internal/modelcatalog ./internal/modelprofile ./internal/responsesadapter ./internal/cli ./internal/teams -count=1`
- `go vet ./...`
- CI workflow `actionlint`
- Expanded catalog/adapter/CLI contract selectors run locally and in the
  Linux CI workflow.
- Isolated Docker `smoke` and `cxp proxy doctor` runs with no provider network
  request and no credential embedded in the image.
- Loopback HTTP verification proves an Anthropic route uses `/messages` and
  its configured `x-api-key` header.

## Compatibility

This prerelease intentionally uses catalog schema v2 and does not retain a
legacy external-catalog reader. Existing official model behavior remains on
the official route; third-party provider credentials remain local-only. Real
provider billing, search quality, rate limits, and provider-side capability
changes still require an operator-owned smoke test with credentials outside
repository CI.
