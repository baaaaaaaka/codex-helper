# v0.1.22-rc.7

## Why

Teams `fork` could reject a valid parent cutoff even though the visible
Codex history was present. Native Codex transcript `response_item` records
carry their turn ID in
`internal_chat_message_metadata_passthrough.turn_id`, but the transcript
parser did not read that field. Fork history materialization therefore could
not find the durable cutoff turn and correctly refused to guess a boundary.

## What changed

- Read the metadata turn ID as a fallback for `response_item` transcript
  records, while preserving the existing explicit turn-ID precedence and
  cutoff safety checks.
- Added parser coverage for metadata-only and explicit turn-ID records.
- Updated the deterministic fork Docker fixture to use the native transcript
  shape and selected the regression in core CI.

## Validation

- Full `internal/teams`, `internal/teams/store`, `internal/cli`, and
  `internal/helperruntime` package tests.
- Core transcript and fork CI test patterns.
- Teams fork Docker smoke.
- Compose fault matrix: five scenarios across JSON and SQLite stores.
- GitHub Actions workflow lint and CI shard-selection tests.

## Compatibility

The change is limited to transcript turn-ID extraction. Existing explicit
`payload.turn_id`, nested `turn.id`, cutoff validation, native fork behavior,
and refusal-to-guess safety boundaries are unchanged. No Teams service state
format or public protocol is changed.
