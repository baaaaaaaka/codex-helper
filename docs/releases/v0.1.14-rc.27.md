# v0.1.14-rc.27

## Why this prerelease exists

This candidate fixes the failure mode where a CXP/ChatGPT desktop proxy stays
in `reconnecting` after a laptop lid close and wake. The old recovery path saw
the SSH tunnel exit while the host was suspended or while the network stack was
still rebuilding. It could then probe too early, spend the shared recovery
budget on attempts that could never succeed, or race shutdown while replacing
the SOCKS backend. Once the durable budget was exhausted, the process correctly
blocked further restarts, but that safety valve made the original reconnecting
symptom permanent until a new process was started.

The goal of this prerelease is to make the recovery decision explicit:

`power/network hint -> bounded host readiness gate -> candidate tunnel ->
TCP/SOCKS/route validation -> generation swap -> bounded old-generation drain`

Power and network notifications are advisory. The host probe and the
candidate's route probe remain authoritative, so a notification storm cannot
turn into a restart storm.

## What changed

- Added a user-mode host-state observer abstraction. Windows uses
  `PowerRegisterSuspendResumeNotification` and `NotifyIpInterfaceChange`;
  macOS uses IOKit power notifications and SystemConfiguration network
  notifications on a pinned run-loop thread; polling remains the fallback for
  unsupported platforms and no-cgo macOS builds. None of these paths requires
  administrator privileges.
- Added a host readiness gate after wake/network events. While suspended, the
  monitor waits for a wake event instead of repeatedly selecting an already
  closed tunnel channel. After wake it performs bounded interface/endpoint
  probes with backoff, and only then considers a recovery candidate.
- Added a wall-clock probe-gap fallback. It detects a sleep interval even when
  the platform's monotonic clock does not advance during suspend, and turns the
  gap into a host-gated wake hint. A false positive costs one bounded probe; it
  cannot directly consume the recovery budget.
- Made candidate construction cancellation-aware and lifecycle-safe. A
  candidate is visible to health and shutdown cleanup as soon as it exists,
  close/recovery ownership is serialized at the generation switch, and a
  candidate cannot be installed after shutdown has begun. Observer start/close
  transitions are also one-way and reject a start after close.
- Kept the durable restart/request circuit breaker and moved restart admission
  after host gating and backoff but before candidate resource allocation. Sleep
  and network-wait paths therefore do not spend the budget, while construction
  and replacement failures remain bounded across process replacement.
- Made host probing route-aware. Explicit ProxyJump/ProxyCommand/`-J`/`-W`
  routes do not cause a local probe to dial the final destination directly;
  the actual SSH/SOCKS route probe is used as the authority instead.
- Exposed power state, host network state, host readiness, probe counters,
  recovery generation, candidate state, and the last recovery cause through
  the existing local health endpoint. These fields are additive and do not
  change the proxy protocol.

## Compatibility and operational boundaries

The change is unprivileged and keeps the public HTTP listener stable during a
backend replacement. It does not install a service, alter firewall settings,
or require a kernel extension. Native notifications are best-effort hints;
polling and target-specific probes provide the fallback when an OS API is
unavailable or an event is dropped. A real physical lid-close/device test is
not reproducible on every hosted CI runner, so the tests combine deterministic
fault labs with native macOS and Windows builds and unprivileged platform
validation.

## Validation

The prerelease is gated by:

- observer lifecycle, wall-clock gap, power/network state, route-target, and
  bounded recovery unit tests;
- repeated Linux, macOS, and Windows loopback fault-lab runs;
- race-enabled package tests and the full Linux race suite;
- macOS cgo/native validation on hosted arm64 and Intel runners;
- Windows native observer, process-lifecycle, and proxy validation;
- the Docker SSH/SOCKS disconnect/reconnect smoke and the release workflow's
  GoReleaser, installation, container, and upgrade-compatibility checks.

This is a prerelease for validating sleep/wake proxy recovery. It does not
replace the existing stable `v0.1.14` release.
