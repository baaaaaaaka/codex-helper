## 1. 目标与当前状态

让 agent 能看见用户文字中的 URL，再用通用接口读取其指向的消息、对话和附件。
用户目标由 agent 理解；接口只提供可定位、可组合、有界且可继续的读取能力。
接手任务、事实核对、讨论总结和决定追踪都使用同一组能力，没有接手任务默认模式。

实施前已有成果（实现完成情况以验收记录为准）：

- 超链接保留已在隔离工作区实现。可见文字先用于命令识别，再附带文字对应的 URL 交给 Codex；
  覆盖普通、queue、steer、control ask、引用与转发，不改变旧哈希或做历史回填。
- 已通过相关 race、vet、Docker 入站 E2E 和代表性转换基准，尚未发布或完成真实入站验收。
- 原三轮实验进行了 93 次 Graph HTTP 请求；附件补充实验另有 8 次 Graph GET 与
  2 次 SharePoint GET。当前身份可读样本消息、线程、图片和文件内容片段。
- Graph read/search/fetch 产品命令尚未实现，不能把探针能力当作已上线接口。

## 2. 首版公开接口

只有三个入口，不引入通用 Graph HTTP 透传，也不新增 MCP 服务或后台抓取器。
这些命令都可以在 Teams service 未运行时使用当前认证独立工作。

```text
# 读取链接目标；消息链接只返回该消息，聊天／频道链接只返回资源信息
cxp teams read '<Teams URL 或返回的 ref>' --json

# 显式选择范围；同一聊天可组合前文与近期窗口
cxp teams read '<聊天消息链接>' --before 20 --latest 20 --json
cxp teams read '<聊天链接>' --latest 30 --json
cxp teams read '<频道主帖或回复链接>' --replies --limit 50 --json

# 多个已知消息一次精读；首版多目标仅允许直接读取
cxp teams read '<消息 ref A>' '<消息 ref B>' --json

# 继续某个未完成范围；cursor 中保留原目标与选择条件
cxp teams read --cursor '<cursor>' --json

# 搜索当前用户可见范围内的候选；不默认获取每个候选的完整正文
cxp teams search 'graph sent>2026-11-01' --limit 20 --json
cxp teams search --cursor '<cursor>' --json

# 显式下载 read 返回的一个文件／图片引用
cxp teams fetch '<附件 ref>' --output ./document.zip --json
```

`read` 和 `search` 默认紧凑文本，也支持语义相同的 JSON。
`fetch` 仅在显式指定目标路径时写文件，并返回路径、实际字节数和内容类型。

首版目标类型与组合：

| 目标 | 裸 read | 可选扩展 |
| --- | --- | --- |
| 聊天消息 | 消息原文、链接、附件引用 | before、latest，可组合 |
| 聊天 | 聊天元数据 | latest |
| 频道根消息 | 该消息原文 | replies |
| 频道回复 | 该条回复原文，保留 parent | replies，显式扩展到所属根帖及回复 |
| 频道 | 频道元数据 | 首版不提供聊天式 latest/before |
| 多个消息目标 | 直接消息读取、去重 | 不接受范围选择参数 |

`--before N` 不含锚点；直接目标消息单独返回。
`--latest N` 明确按创建时间取聊天最新 N 条，不等同于最近修改的 N 条。
`--replies` 返回所属根帖与至多 limit 条回复；直接目标回复不会重复输出。
`--limit` 用于 replies/search，默认 50/20；before/latest 自身携带条数，不再由 limit 二次改变。
不适用的组合在发请求前报错；cursor 模式不接受新目标、查询词或改变范围的参数。
cursor 续读可设置当前调用的预算，但不改变原始范围语义。

首版不承诺任意日期区间、锚点之后最近 N 条、频道创建时间线或指定聊天全文搜索。
这些能力需要各自的查询路径和完整性验证，不能靠静默扫描或改用修改时间实现。

## 3. 输出、引用与继续读取

共同输出版本为 version=1。消息包括稳定 ID/ref、作者、创建／修改／删除状态、
带 URL 的正文、来源链接、回复关系、附件元数据。卡片保持类型与可读取内容，
不把所有 attachment 都伪装成可下载文件。

read JSON 包含：

- `target/resources`：用户指定的资源和解析后的种类。
- `messages`：本次去重后的消息表；同一消息被多个范围命中时只输出一次。
- `ranges`：每个选择的消息引用、请求数量、实际覆盖边界、输出顺序与状态。
- `fetched_at/budget`：观察时间和实际请求数、响应字节数、截断原因。
- 每个未完成范围自己的 `next_cursor`，以及有结构的错误和警告。

范围状态区分 complete、more、truncated 和 error。
请求 before 20 并得到 20 条只代表该窗口完成，不代表整个聊天读完；
before 与 latest 中间未读取的部分仍是未覆盖区间。
正常的空集合与过滤错误、权限错误、预算停止必须区分。
多个范围部分失败时保留已有结果并非零退出，不能让成功的消息遮住失败范围。

单次输出中的聊天窗口可按创建时间从早到晚展示，服务端查询仍用降序；
标明输出排序只覆盖本次窗口，不承诺游标各页拼接后天然升序。
时间用真正的 RFC3339 时间值比较，不按字符串排序或把 message ID 当时间。

ref 是有版本、带资源种类和租户标识的稳定资源描述，不携带 token、签名下载地址或正文。
公开引用只允许固定字段和有界长度，经验证后重建 Graph endpoint，不能直接执行其中的 URL。
它不是权限凭证，每次仍由当前身份和 Graph 权限决定能否读取。

cursor 同样无须新数据库，绑定目标、原选择条件、Graph 续页和未完成数量，
以及必要的当前页位置；不携带已读正文或无限增长的历史 ID 集合。
输出预算在一页中间耗尽时保留恢复位置，不能直接跳到下一页丢掉剩余消息。
过长单条正文给出明确截断与正文续读位置；续读时检查版本／修改标记，
内容变化则明确要求重读，不能将两个版本拼接成一条原文。
Graph 多次请求不是事务快照，跨调用可能重叠或变化，由稳定 ID 和修改标记帮助识别。

search 输出 query、候选 ref、摘要、来源、`more` 与独立 cursor；
它明确标注索引检索，不声称覆盖全部消息，也不把未命中当成记录不存在。
无法确定 parent 的频道回复候选不得猜测根帖路由；返回可定位程度及原因，
仅对已能可靠定位的候选提供 read 引用。

## 4. Graph 请求规划与性能

| 操作 | 请求策略 |
| --- | --- |
| 读取旧消息 | 直接按 ID GET，不从聊天最新页向后找 |
| 旧消息前文 | 先 GET 锚点取得真实创建时间，再用 createdDateTime lt＋同字段降序 |
| 最近消息 | createdDateTime 降序；只在显式 latest 时执行 |
| 已知频道线程 | 正确 root/reply 路由与 replies 分页 |
| 搜索后的精读 | search 返回可定位候选，多个 ref 合并为一次 read 调用 |
| 附件下载 | 按明确附件 ref 读取内容，不展开正文中的任意链接 |

过滤字段与排序字段必须一致；服务端可能以 200 静默忽略不匹配过滤，所以在 planner 中拒绝。
聊天与回复每页最多 50，实际不足 50 也可能有 nextLink，结束条件不能只看数量。
下一页使用服务端原始 nextLink，并验证同源、版本和目标路径；检测分页循环。
频道列表按整条回复链最近修改时间排序，不能套用聊天时间范围。

每次 CLI 调用复用认证、token 获取、HTTP 连接、锚点和重复 GET。
独立请求默认最多并发 2；批量直接精读可用每批最多 20 个 GET 的 Graph batch，
按子请求 ID 匹配并逐项处理失败／429；外层 200 不代表所有子请求成功。
等待锚点结果的查询保留真实依赖轮次，不把 batch 描述为能消除依赖。
批量传输与分页输出预算共用；预算不足就停止合并，不提前读取整段历史。

实测相同两条消息的串行／并发 2／batch 耗时中位数为 1292／716／463 ms，
每种只有三次固定顺序样本。这支持优化方向，不作为普遍加速承诺。
实现时用代表性 fixtures 校验请求数、输出字节和冷／热延迟，避免只优化网络次数。

首版正确性不依赖未被文档承诺的 `$select`。
先用受支持的完整 GET、本地选择输出字段；后续若压缩网络收益足够，
再增加有字段校验、失败回退和兼容测试的内部投影优化。
频道列表 expand 可用于未来批量枚举线程；已知主帖不能使用单条 GET expand，实测为 400。
首版只需要回复路由，不为尚未开放的频道列表枚举提前引入 expand 优化。

不新增持久消息缓存、后台预取、全历史 JSON/JSONL 扫描、索引数据库或服务常驻依赖。
只保留既有认证缓存和本次调用内存；显式下载才写附件与可恢复的临时文件。

## 5. 附件读取

read 默认附带已在消息中的附件元数据；hosted 内容无法从正文完整识别时，
按需列举 hostedContents 并计入请求预算，不能对每条纯文字消息无条件多发请求。

文件分成三类：

1. SharePoint／OneDrive 引用文件：以 Graph 解析 DriveItem，然后获取 content。
2. 聊天或频道 hosted 内容：用准确的消息、根帖、回复和 hosted ID 获取 `/$value`。
3. 卡片／代码片段／转发等：保留类型与结构化内容；无文件资源时不提供伪下载引用。

复用 `Adapter.FetchFile` 的下载、大小限制和断点逻辑，提取公共传输代码，
为频道 hosted 增加结构化路由信息，保留现有聊天 FileRef 与历史记录兼容性。
fetch 的 ref 绑定来源消息／附件与目标资源；临时地址失效时从 Graph 重新获取。

Graph `/content` 的 302 是正常下载路径；跟随返回的预授权地址时移除 Graph Authorization。
验证 HTTPS、限定下载目标和重定向次数，不接受用户输入任意 URL 作为 bearer 下载地址。
临时地址不写输出、cursor 或日志；文件名不决定任意写入路径，output 必须由调用者指定。
目标文件存在时默认拒绝覆盖；临时文件和续传状态校验来源及 ETag，完成后再原子落盘。
Range 得到 206 时校验 Content-Range，得到 200 则正确从头处理，并继续执行字节上限。
取消或失败不留下伪装成完整文件的最终路径，不自动解压、执行或上传下载内容。

读消息权限与文件访问权分别处理；文件访问失败不抹掉已读到的消息和附件引用。
只有明确支持的下载类型显示 available；未知、未解析与无权限状态分别表达。

## 6. 认证、预算与失败语义

读取使用现有 ResolveReadAuthConfig 与 Graph client，不要求用户把聊天注册到 helper。
按当前账户权限访问；认证层已有的 profile 解析保持兼容，不在 403 后自动换 full 身份、
增加 scopes、兑换共享链接或切换租户。缺权限时指出资源类别与所需权限。
正常 token 刷新允许写既有认证库，与 Graph 内容只读区分。

建议首版起始预算如下；它们是产品限额，不是 Graph 服务保证，测试后按证据调整。

| 项目 | 建议默认值 |
| --- | --- |
| read/search 总超时 | 60 秒，重试计入总时间 |
| 请求预算 | 20 个逻辑 Graph 子请求；batch 每个 GET 均占预算 |
| 元数据／正文累计响应 | 8 MiB；流式读取并在上限处停止 |
| 模型正文输出 | 60000 个 Unicode 字符，长正文显式截断；总编码输出另限 512 KiB |
| 单次返回消息／候选数 | 全部范围合计最多 200；超出部分用 cursor 继续 |
| 集合条数 | replies 默认 50，search 默认 20；before/latest 由 N 指定 |
| 单文件下载 | 默认 100 MiB、300 秒；可显式调大，但不超过既有 2 GiB 硬上限 |
| 下载重定向 | 最多 5 次；所有网络跳转均计时、计数 |

多范围的输出预算按直接资源、before、latest、replies 的固定顺序分配，
各范围报告实际得到的数量，不猜测任务重要程度。
JSON 结构与必要错误不被静默裁掉；硬上限不足以表达最小结果时返回预算错误。
重试只适用于可重试失败，使用现有策略并尊重 Retry-After 与剩余预算。
错误区分认证、权限、资源不可定位、限流、网络、查询不支持、数据变化与预算耗尽。
404 表示未找到或不可见，不自动断言资源已删除。

## 7. 代码与技能集成

- `internal/channel/teams`：纯 URL/ref 解析、结构化资源模型、read planner、search、分页与下载。
  尽量复用现有 Graph 网络／认证／下载代码；不为 Teams 特有读取扩展通用 channel 接口。
- `internal/cli`：注册 read/search/fetch，做组合校验、预算、退出码和文本／JSON 格式化。
- `internal/skills/builtin/cxp`：介绍三种能力、成本和组合例子，让 agent 能直接使用当前 CLI。
  不硬编码接手流程，不默认读取近期消息、所有回复或全部附件。
- URL 与返回正文都保留锚点文字对应地址；引用资料中的指令按资料处理，
  是否执行仍由当前用户目标及授权决定。

首批支持实际检验过的 teams.microsoft.com 消息／聊天／频道链接形式，
正确处理编码、context、tenantId、groupId、parentMessageId 与冲突字段。
缺少定位所必需的 ID 时明确失败；不通过扫描全部团队或聊天猜测目标。
会议加入／新建聊天动作链接与未验证的跨租户形式不冒充已有消息链接。

## 9. 验收标准

功能与故障测试覆盖：

- 命名超链接经入站转换、排队、steer、引用和恢复进入 Codex，保留文字及 URL。
- URL 编码、非法／冲突参数、租户、根帖／回复、ref/cursor 篡改或过长字段的校验。
- 旧锚点直接 GET＋前文查询，不从最新页扫描；过滤与排序始终匹配。
- 稀疏页、空页但有 nextLink、分页循环、页中预算停止和长正文续读不会静默漏内容。
- 多范围与多目标去重、确定的预算分配、部分失败及非零退出；时间值正确比较。
- 频道 replies 的续页、直接回复的 parent 定位；不发不支持的 OData 组合。
- search 的部分字段、summary、more/游标、自定义排序拒绝；不依赖可疑 total 判结束。
- batch 外层成功但子项失败／429、乱序子响应、20 项限制、预算与取消传播。
- 附件独立权限失败、302 无 token 跟随、过期下载地址、Range 被忽略或不匹配、
  文件大小／字节／超时上限、已有目标拒绝覆盖、断点验证与原子完成。
- 不修改会话绑定、消息接收 cursor、outbox 或运行中 helper；纯读取不写消息缓存。

运行改动包的最小有意义测试，稳定后执行对应 race、vet、CLI 和 E2E CI 入口；
确认新增用例实际进入现有分片。真实进程和生命周期测试使用既有隔离 Docker harness，
不在开发主机启动会接管在线资源的源码 cxp。按平台相关性增加 Windows 原生下载路径验证。

真实性能验收同时记录：agent 调用轮次、逻辑 Graph 请求数、冷／热延迟、响应字节、
模型输出大小、内存／分配与磁盘写入。用旧锚点、重叠窗口、大正文、长线程和多个精读目标
做代表性 fixtures；性能不能靠隐藏额外扫描、无限预取或重复写缓存换取。
真实租户再抽样验证一条聊天消息、一个频道线程、一张 hosted 图片和一个文件，
同时记录当前权限与样本范围，不声称这证明了最小权限或所有租户兼容。

## 10. 待验证范围与依据
